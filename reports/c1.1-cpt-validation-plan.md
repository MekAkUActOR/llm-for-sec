## 0. 一句话结论

用 **3 个变体 × 240 步（各 125.8M token、各 3.52h）**、**共 ≈12.3 GPU 小时**
（含评估），在 `probe_ppl`(v0.4 干净口径) / `probe_longctx`(16 次/格新口径) /
`baseline_eval --prompt-format chat`(v0.2.1 + v0.3-gen) 四套现有仪器上回答一个可证伪问题：

> **在同等 token 预算下，C1.1 目标配比相对于 C1-full 复刻，是否让"当前曝光≈0 的两个优先域
> （ai_safety / privacy）"的 PPL 降幅多出 ≥5 个百分点？**

"是" ⇒ 方向被验证，进入升级条件审查（§3.4）；
"否/未达可区分" ⇒ **不得**购买 ≥35h 全量重训，改为扩预算或改判据。

## 1. 假设与可证伪判据

### 1.1 被验证的命题

`review` §4.3 判定 C1 的 D6 优先域"几乎未实现：ai_safety 0% / privacy 0.013% / code 0%"，
且 sec 域已出现饱和（72M→434M 曝光，×6，只换 −1.6pp，`review` §2.1）。
C1.1 的核心主张因此是**结构性的**：把份额从"已饱和的安全域 + 超配的通用回放"转移到
"曝光为零的优先域 + zh 安全域 + 载体结构层"。

**要证伪的是**："换个配比在同等预算下能让优先域学得更快"。
如果 240 步、125.8M token 内 C1.1 混料在 ai_safety/privacy 上并不比 C1-full 混料学得快，
那么"补料 → 全量重训"这条 35h 投入的因果链在第一环就断了。

### 1.3 明确**不列入**验收的三件事（避免 Goodhart）

1. **不以行为改善为 CPT 的验收项**。`docs/05:121` 的预期是预训练阶段"不练对齐，
   预期 ASR≈1 维持"；行为改进是 M2/M3 的职责。把行为当 CPT 验收项会同时污染两阶段的归因，
   并把 `docs/00 §9.3` 的 Goodhart 风险引进来。
2. **不用绝对门禁线（sec 相对 base 降 ≥25%，`docs/05 §7`）作为变体淘汰依据**。
   240 步 / 125.8M token 到不了 1,088M token 的效果；用绝对线会把"预算不足"误判成"配比不对"
   ——这正是 §4-⑤ 列出的最大内部效度威胁。绝对线只作**曲线记录**，只对"上一同类产物"作增量比较
   （`docs/01 §11.2` 方差纪律）。
3. **不用 raw 口径读数**（`docs/01 §11.1`）、**不用 `discarded` 产物作基线**
   （`m2full` 状态 = `discarded`，`m25_exit_verdict.py:56-60`；`docs/01 §11.4`）。

### 1.4 一条必须先修的仪器缺口（否则无法用现行判定器）

`m25_exit_verdict.py:53` 硬编码 `PROBE_VER = "v0.3"`，G2 只读 `reports/ppl-<tag>-v0.3.json`。
但 v0.3 的 `privacy` 与 `general_en` 正是**污染口径**（`docs/research/probe-contamination-audit.md`：
`c0_gdpr` 64.9%、`c1_enwiki_gen` 23.7–26.4%），S0 才因此新建 v0.4
（`reports/probes-v04-build.json`：privacy 换源 ICO、general_en 取 C1 采样补集，
对 `sec_c1_full` 抽样 60,000 行 0 命中）。**C1.1 的判据必须用 v0.4**，于是有两种走法：

- **走法 A（不改代码）**：变体评估**同时跑 v0.3 与 v0.4**，把 v0.3 喂给现行判定器、
  v0.4 作主判据；代价 +0.92h GPU（§3.2），且报告里必须显式标注"判定器读的是污染口径的 v0.3"。
- **走法 B（需授权）**：把 `PROBE_VER` 参数化为 `--probe-ver {v0.3,v0.4}`，
  v0.4 优先、v0.3 回退。属"判据变更"，按 `docs/01 §11.5` 需留痕
  （定义处 + 针对的边界 + 变更日期 + 批准人）→ 列入 §6-②。

本设计**默认走法 A**（不改既有脚本），把走法 B 作为优化项。

## 2. 实验设计

### 2.1 三个变体

共同点：**同一起点**（Qwen3-0.6B-Base 快照 `da87bfb608c14b7cf20ba1ce41287e8de496c0cd`，
`configs/c1_full.yaml:8`）、同一预算（240 步）、同一套超参、同一随机种子。
**唯一变量是数据集文件**。起点选 base 而不是 `c1-full`：三变体同起点同预算，
差异的唯一来源是混料；从 `c1-full` 续训是"修复既有权重"的另一个问题，不在 C1.1 范围内。

| 变体 | 名称 | 配比（按 token） | 目的 |
|---|---|---|---|
| **V0** | C1-full 复刻（**对照**） | general_en 48.63% / general_zh 11.43% / 安全域 39.94%（唯一 217.2M **写两遍**，其中 redhat 38.26% / cve 32.27%） | 复现 C1 的配比结构，作为"同等预算下旧配比能走多远"的基线 |
| **V1** | C1.1 目标配比 | general_en 26% / general_zh 22% / security_en 24% / security_zh 4% / ai_safety 10% / privacy 4% / code 8% / 载体结构层 2%（**1 epoch，无重复写入**） | 待验证的混料方向（`reports/c1.1-mix-design.md` §2.1） |
| **V2** | 归因变体（只补 zh，不补优先域） | general_en 34% / general_zh 26% / security_en 24% / security_zh 4% / ai_safety 6%（存量） / privacy 2%（存量） / code 4%（t6 存量的一半） / 载体 0% | **归因**：若 V1 优于 V0 而 V2 不优于 V0 ⇒ 增益来自优先域补齐；若 V1≈V2 ⇒ 增益只来自 zh 份额，则应改走"仅提高 zhwiki 采样率"的低成本路径（纯 CPU） |

**为什么 V2 值得花 3.52h**：它区分的是两条成本差两个数量级的路线
（"只调 zh 采样率"vs"采购/合成 350M 新料"）。这个区分是整个 C1.1 里最贵的一次决策，
用 3.52h 买它是便宜的。

### 2.2 步数 / token 预算与折算依据

**折算基准（来自实测，非估算）**：

| 量 | 值 | 来源 |
|---|---|---|
| C1-full 规模 | 1,088M token（复算 1,087,789,926） | `docs/01 §3.1`；`reports/c1.1-mix-design.md` §1.1 |
| C1-full 步数 / 时长 | 2,072 步 / 30h20m = **109,200 s** | `docs/01 §3.1`；`docs/05:119,121` |
| 步时 | **52.8 s/step** | `docs/01 §3.1`（`docs/05:119`） |
| 每步 token | bs1 × accum128 × cutoff 4096 = **524,288 token/step** | `configs/c1_full.yaml:34-35,19` |
| 有效吞吐 | 524,288 / 52.8 = **9,930 token/s = 35.75M token/h** | 由上两行推导 |
| 每变体预算 | **240 步 × 524,288 = 125,829,120 token ≈ 125.8M** | 本文 |
| 每变体训练时长 | 240 × 52.8 s = 12,672 s = **3.52 h** | 本文 |

> **顺带修正一处文档不一致**：`docs/05:107` 与 `docs/01 §3.1` 都写"吞吐 7.3k tok/s"，
> 但那是 C0/202M 时代的 72.1 s/step 读数；C1-full 的实跑口径 52.8 s/step 对应 **9.93k tok/s**。
> 7.3k 与 52.8 s/step 不能同时成立。C1.1 的预算一律用 52.8 s/step（更保守的是用时更长的那个）。

**为什么 240 步这个量级是合适的**：
- 它是 C1-full 的 **1/8.6 步**、**11.6% token**，训练成本 **3.52h vs 30.3h** → 满足"远小于 35h"；
- 项目内已有先例：M1.5（`m15`）**114 步**（≈59.8M token、≈2.2h）已足以让 sec PPL 与
  长上下文读数发生可观测移动（`docs/05:120`：`m15` = lr **2e-5**、cutoff 16384、bs1×32×16k = 524,288 token/step、≈114 步 ≈2.2h；`reports/longctx-*` 阶梯），
  说明百步量级的 CPT 在本项目是可测的；
- 三变体总计 10.56h，仍只占一次 35h 重训的 **30%**，却能同时给出 3 组互相对照的读数。

**两个刻意的设计选择（须在报告里声明）**：

- **调度形状**：三变体各自跑完整 cosine（240 步），而不是从 C1 的 2,072 步计划里截前 240 步。
  后者会让所有变体停在 lr ≈ 1e-4 附近（PPL 分辨率更低）；前者让每个变体在同一调度形状下
  到达各自的端点。**代价**：与 C1-full 的调度不可横向比较，绝对值只能与 base 比。
- **warmup 占比**：240 步里 20 步 warmup = **8.3%**，而 C1-full 是 20/2,072 = **0.97%**。
  这是一个已知局限：三变体完全一致 ⇒ 不影响**变体间**比较，但绝对值偏保守。

**为什么 lr 取 1e-4 而不是 M1.5 的 2e-5**：`m15` 的 2e-5 是"往**已有安全模型**里打知识针"
（起点是 m16-32k 产物，`docs/05:120`）；C1.1 变体是**从 base 起步的预训练**，与 C1 同属一个
训练体制，必须与对照 V0 用同一 lr 才能把差异归因于混料。若把 lr 降到 2e-5，
240 步的效应量会被压小，反而放大 §4-⑤ 的"预算不足 vs 配比不对"混淆。

### 2.5 每变体验收判据与淘汰规则

| 规则 | 触发条件 | 动作 |
|---|---|---|
| **R1 一票否决** | H5 任一红 | 该变体不得发射；修混料后重跑前置闸 |
| **R2 守门否决** | H2 / H3 / H4 出现**可区分的 `worse` 轴**（三态判定，`secfm/eval/stats.py:110-147`） | 该变体**淘汰**，不必再看 H1（长上下文或通用能力被牺牲掉的混料没有讨论价值） |
| **R3 方向否决** | H1a 两域都未达 +5pp **且** H1b 差于 V0 − 2pp | 判"**混料方向未验证通过**"；除非方向为负且可区分，否则措辞只能是"未达可区分"（`docs/01 §11.2`） |
| **R4 未达可区分** | \|Δ(V1−V0)\| 落在预注册 δ=5pp 内的灰区（2–5pp） | 判 `undecided` → 走 §3.5（Phase B）或改判据；**不得**升级全量重训，**不得**写"通过" |
| **R5 归因否决** | V2 ≈ V1（互不可区分）且两者都优于 V0 | 增益归因于 **zh 份额** ⇒ 优先执行"仅提高 zhwiki 采样率"的纯 CPU 路径，**推迟** 350M 新料采购 |
| **R6 中间档保留** | 任一变体 `save_total_limit < 3` 或中间档丢失 | 违反 `docs/01 §7.3`；该轮读数不得作为决策依据（先例：`save_total_limit=2` 导致 m25 中间档永久丢失，`review` §1.4/§12-11） |
| **E1 例外登记（必须显式，不能默认）** | V1 的 `general_en`/`general_zh` 相对 **V0** 回升 > +10%（G2 增量轨报警）**但**绝对轨（相对 base）仍在 +10% 内 | **不淘汰**，但必须写一条例外登记：定义处（G2 增量轨）+ 针对的边界（平行混料臂之间）+ 变更日期 + **批准人**（`docs/01 §7.2`/`§11.5` 要求）。理由见下方"为什么要这条例外" |

> **为什么要 E1（本设计最容易踩的判据—证据接口坑）**：
> `m25_exit_verdict.py` 的 G2 增量轨（`INCREMENT_CAP = 10.0`，`:64`；`ppl_gate`，`:202-244`）
> 是给**串行阶段**设计的——"上一同类产物"是你**要保住的**成果。
> 但 V0/V1/V2 是**平行臂**：V1 的通用回放份额（26%）比 V0（48.63%）低 22.6pp，
> 因此 V1 的通用 PPL **必然**比 V0 差，很可能超过 +10%。
> 若机械套用增量轨，判据会把"**这正是被验证的设计取舍**"读成"退化"并淘汰 V1 ——
> 即用放大镜下的规则杀掉实验组。正确的分工是：
> - **绝对轨（vs base）作守门**：V1 不得出现净退化（≤+10%）；
> - **增量轨（vs V0）作信息项**：它测出来的差值**就是"降低通用回放换优先域"的价格标签**，
>   是决策输入，不是淘汰理由。
>

## 4. 风险与缓解

| # | 风险 | 机制 | 缓解 |
|---|---|---|---|
| ① | **过拟合小验证集 / 探针与语料同源** | v0.1.1 的 `privacy` 探针取自 GDPR 序言（与 `c0_gdpr` **64.9% 篇级重叠**）、`general_en` 探针取自 enwiki P1 分区（与 `c1_enwiki_gen` **23.7–26.4%** 重叠）。V1 降低 enwiki 份额会让 `general_en` PPL 读数变差——这是**真实效应**；但 v0.1.1 的既"改善"读数本身就是**污染虚高**（`docs/research/probe-contamination-audit.md` §"对既有读数的影响评估"） | 主判据一律 **v0.4**（换源、对 `sec_c1_full` 抽样 60,000 行 0 命中）；v0.1.1 只作历史对照并强制加注；`privacy`/`general_en` 两域 **v0.3↔v0.4 数值不可直接比较**（同文件 §2） |
| ② | **评测污染** | v0.2.1 是**在训载体**，用它只能证明"同载体、新句式"（`review` §4.4）；未见载体命题必须由 `v0.3-gen` 承担。而 V1 新增的 **carrier 合成语料**恰恰最容易与 v0.3-gen 的 image/av metadata 机制撞车 | H5-2 载体断言**不可省**；生成器的留出载体清单作输入断言（`docs/01 §10.3` 规则 5）；v0.3-gen 每格 n ≥34 的样本量下限（`docs/01 §11.2`）→ 现状鲁棒性条 35+35，达标 |
| ③ | **与 SFT 阶段目标耦合** | (a) 把行为改善当 CPT 验收项 = 与 M2/M3 职责混淆 + Goodhart（`docs/00 §9.3`）；(b) 若把 16 个 procured 源的"判断侧"按新格式入 CPT，其**输出先验**须与 SFT 契约 `{answer, refuse, report}`（`review` §5.3）一致，否则 CPT 引入一个与 SFT 冲突的先验 | §1.3-1 明确不列入；入 Stage 1 的语料必须**去掉指令-响应对结构**、只保留描述层文本（`docs/04 §0` 分层原则） |
| ④ | **统计效力（无种子重复）** | 单次训练、无重复 ⇒ 变体间差值没有方差估计；`docs/01 §11.2` 明令"单次训练、无种子重复的阶段间幅度差不得作为结论" | 三变体共享同一 lr 计划与种子（把训练随机性在变体间压到最小）；预注册 δ=5pp；< δ 只能写"未达可区分"；灰区走 Phase B 并**换种子**以取得经验方差 |
| ⑤ | **预算不足 vs 配比不对的混淆（最大内部效度威胁）** | 240 步可能太短，效应量小于仪器分辨率 ⇒ 把"预算不足"误读成"配比不对" | 主判据选**首剂效应最大的两个域**（ai_safety/privacy 在 C1-full 曝光 ≈0，先验上最可能在 240 步内出效应）；始终保留 V0 对照（判据是**相对差值**不是绝对值）；R4 明确把灰区判成 `undecided` 而非失败 |
| ⑥ | **warmup 占比与调度截断** | 240 步里 warmup 20 步 = 8.3%（C1 为 0.97%）；三变体各自完整退火 ⇒ 绝对值与 C1-full 不可比 | 三变体完全一致 ⇒ 不影响变体间比较；报告中显式声明"与 C1-full 的调度不可横向比较" |
| ⑦ | **GPU 独占与排期争用** | 10.56h 训练 + 1.77h 评估 = 12.33h 独占单卡，与 M3 DPO（`docs/07`）、S1 待办（`docs/01 §12-6/7/11`）争用 | CPU 侧补料（zhwiki 重采样、载体合成）与之并行；变体按 V0→V1→V2 顺序，**V0 完成即可先出对照读数**，可中断 |
| ⑧ | **判定器读污染口径** | `m25_exit_verdict.py:53` 硬编码 `PROBE_VER="v0.3"`，G2 只认 v0.3 | 走法 A（同时跑 v0.3，报告显式加注）或走法 B（参数化，需授权留痕） |
| ⑨ | **串行判据误杀平行臂（本设计最大的判据—证据接口坑）** | G2 的增量轨（`INCREMENT_CAP = 10.0`，`m25_exit_verdict.py:64`）是给**串行阶段**设计的；V1 的通用回放份额比 V0 低 22.6pp，通用 PPL **必然**比 V0 差，很可能触发 G2 增量报警 ⇒ 判据会把"这正是被验证的取舍"读成"退化"并淘汰 V1 | §2.5-**E1**：绝对轨（vs base ≤+10%）作守门、增量轨（vs V0）降为**信息项**（它就是"降低通用回放换优先域"的价格标签），并要求**书面例外 + 批准人**（`docs/01 §7.2`/`§11.5`）。先例教训：绝对线跨阶段复用正是 `review` §3.2-D1 记的判据设计缺陷 |
| ⑩ | **记账风险（与混料设计耦合）** | 16 个 procured 源的 `est_tokens` 目前是 0；若在未修正前把它们计入混料，会出现"配比达标但账目为 0"的自相矛盾 | 先应用 `reports/c1.1-mix-design.md` §4.5 的 manifest patch（需 §6-① 授权） |
