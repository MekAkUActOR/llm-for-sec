## 5. 假说可否证性

本修复基于假说"**m2-calib 的 needle 缺口 = 未训 T13-retrieval/T10-multiturn**"。
可否证预测：
1. 若训后 needle 显著上升 → 假说成立（且给出剂量-反应斜率）。
2. 若训后 needle 不动 → 假说不成立；needle 差异另有来源（例如 m25-full 的
   17,210 步总量本身、或 warmup/调度差异），应转而比较 m15→m25full 的训练配方差异。
3. 若 needle 上升但契约/泛化崩塌 → 说明**当前架构下"补长上下文"与"保契约/泛化"不可兼得**，
   这是比 C 路更强的负面结论，必须写入 `docs/01 §7.1` 并重新规划 M3 前置条件。

### 7.1 发射前/发射中的配置偏离登记（2026-09-30，**判据未变**，仪表与配方变了）

第 1 版冻结后，配置改了 6 项。**这些改动全部发生在训练之前或训练进行中、且早于任何结果读数**，
不属于"按结果改判据"；但按 §7 必须留痕（改前/改后/边界/依据），否则事后无法解释 360 vs 378 步、
两个不同的 eval 仪器，以及优化器语义差异。批准人：用户（本会话内已裁决"先修 needle 再发 M3"）。

| 项 | 冻结值 | 实际值 | 改因（实测证据） |
|---|---|---|---|
| `eval_dataset` | `sec_sft_v0`（2,324 行） | **`sec_sft_v0_eval300`（300 行）** | **原设计是 in-sample 门禁**：冻结的 2,324 行契约回放与训练集里的契约切片是**同一批行**，in-sample loss 只会单调下降，**原理上不可能报警**。改为 pack×lang 分层挖出的 300 行留出集（seed 20260930），与训练集 id 求交 = 0（看门狗独立复核） |
| `eval_steps` | 50 | **25** | 配合 300 行 eval（单次约 10 s），把契约退化检测延迟从 ≥50 步降到 25 步 |
| 训练行数 | 6,048 | **5,748** | 从上项挖走 300 行；契约占比 38.4% → **35.2%**（仍在 [0.30,0.45] 内） |
| `total_steps` | 378 | **360** | = 5,748 ÷ eff-batch 16。步数变化是上项的直接后果 |
| `save_steps` / `save_total_limit` | 50 / 4 | **20 / 5** | 实测代价：第一次发射在 step 11 被终止（为腾卡做优化器对照探针），`save_steps=50` 未触发 ⇒ **11 步全部投资在零可恢复资产上**。降到 20 步即任何再次终止最多损失 19 步 |
| `optim` | 未指定（= `adamw_torch`） | **`adamw_bnb_8bit`** | **硬件包络驱动的配方偏离**。同数据同 cutoff 4096 的三次 5–6 步对照探针：默认 AdamW 25–51 s/步（单调恶化）、Adafactor 45.9 s/步、`adamw_bnb_8bit` + `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` **4.88 s/步（约 10×）**。选 bnb_8bit 而非 Adafactor 是为**保留 AdamW 语义、最贴近产出 needle 0.875 的参照配方**；代价是优化器数值精度降低。**这是本次唯一的"为跑得动而改配方"项，是残留不确定性来源。** |

**仪器变更的连带后果（按 §11.8）**：契约 eval 仪器由"2,324 行 in-sample"变为"300 行留出"，
**两代读数不可比**。因此 §3 早停规则 1 的基线由"step-50 读数"改为**本 run 首个读数
（step 25 = `eval_loss` 0.054590）**；触发线 = 0.060049（+10%），**连续两次**读数高于它即终止。
本项由看门狗提出、由我裁定并登记。

### 7.2 新增结构性教训（已回流为 docs/01 §11.12）

> **门禁用 in-sample 数据算 loss ⇒ 门禁失效**：契约门禁的 eval 集必须与训练混料**零重叠**，
> 否则 loss 只会随训练单调下降，门禁原理上不可能报警。与 §11.8（仪器变更后基线作废）同类。
> 冻结本预注册时我漏了这一步，是看门狗独立复核（id 求交 = 0）才把它固定下来的。

### 7.3 早停规则 1 的**阈值标定**修订（2026-09-30，训练进行中，**由看门狗提出、我裁定**）

**冻结原文**：契约 `eval_loss` 连续两次读数比 step-50 读数上升 >10% → 终止。

**问题（实测暴露）**：改仪器后锚点落在 step-25 = 0.054590，而该通道**自身健康运动尺度**
就是每读数 0.011–0.032 nats（本 run 实测 0.0546 → 0.0221 → 0.0114，50 步内变动 0.011–0.032，**且全是改善方向**）。
10% 相对阈值在基数 0.0114 时只要 **+0.0011 nats** 就响 ⇒ **比噪声尺度还小**。
反向估算真实失效模式：C 路把 VERDICT 保留从 84/168 打到 8/168（≈45% 行丢失裁决行），
按每 token +2–3 nats、行均摊到 ~30 token ⇒ 整集 **+0.3～0.6 nats**。
⇒ 冻结阈值比真实失效模式**小 1–2 个数量级**，必然误杀；且它**无法区分**"协议格式轻微松动"与"优化抖动"。

**修订后的执行口径（合取）**：
1. **技术触发**（保留原文，不废止）：连续两次 > 0.060049。
2. **终止触发**（必须同时满足）：连续两次读数 **≥ 滚动最小值 + 0.05 nats** **且** 相对涨幅 ≥ +10%。
   `0.05` 的来历：≈ 本 run 健康改善总量（0.043 nats）的同一量级，比单次运动尺度（0.01–0.03）大一档，
   同时比 C 路失效模式（+0.3 nats）小 6 倍 —— 留足检出余量。
3. **仅技术触发时的动作**：**不得**直接 kill；记为 `技术触发 / 判为噪声`，转为**行为学门禁前置**
   （`scripts/diagnose_gen_failure_mode.py` 的 VERDICT 保留率 / `fmt_err`）。理由：`eval_loss` 只是廉价绊线，
   **不是**判定主体；§11.10 第 3 条要求补训的前置验收项**必须**是格式门禁，MUST-2 的行为读数才是判定主体。
4. **本 run 的特殊有利条件**：`save_steps: 20` 给出密集可续档，训练仅约 30 分钟
   ⇒ "事后按行为门禁选档"优于"中途 kill"，因此把 `eval_loss` 明确降级为绊线。

**仍然有效的标定计划（训练结束后、不并发执行）**：用**同一台仪器 `sft_v0_eval300`** 测两个已知档，
把阈值从"推算"变成"标定"：
- (a) 起点 `checkpoints/qwen3-06b-sec-m2-calib`（契约 84/168，健康）；
- (b) C 路契约崩塌档 `checkpoints/qwen3-06b-sec-m3base-topup-e1`（契约 8/168，已知坏）。
**当前 0.05 是 interim 替代品，不是标定值**；此点已列入不确定性清单。

### 7.4 标定完成（2026-09-30，训练结束后串行执行，看门狗交付）

同一台仪器 `sec_sft_v0_eval300`，三档读数：

| 档 | 行为标签 | 契约 `eval_loss` |
|---|---|---|
| `qwen3-06b-sec-m2-calib` | 健康（契约 84/168） | **0.0027** |
| `qwen3-06b-sec-m2calib-needlefix-e1` | 待验收 | **0.0055**（训练期尾读 0.0054822 → 独立复现到 3 位有效数字） |
| `qwen3-06b-sec-m3base-topup-e1` | **已知坏**（契约 8/168） | **0.1424** |

- 实测"健康 → 坏"落差 = **0.1397 nats** ⇒ §7.3 的 **0.05 = 落差的 35.8%，真失效比闸门高 2.8 倍**
  ⇒ **0.05 由"推算"升级为"标定值"**，§7.3 第 2 条正式采用。
- 看门狗自我修正：它先前推算 C 路失效为 +0.3～0.6 nats，**实测 +0.1397，高估 2.2–4.3 倍**（方向不变、幅度错）。
- **§7.3 合取口径获得独立且更强的必要性证据**：真实形态是
  `起点 0.0027 →（25 步，lr 峰值）→ 0.0546 →（自愈）→ 0.00548`。
  step-25 的 0.0546 **不是健康水位而是瞬态损伤峰值**（比起点差 20 倍）。
  任何"相对起点/相对首读"型阈值都会在 step 25 开火，而模型**随后自行恢复** ⇒ **一次确定的误杀**。
  这与 docs/01 §11.7「优化器是一等变量」同源：瞬态由 lr 峰值 + 首个 epoch 的分布切换共同造成。

| **R1** | **权重插值** `θ(α)=(1-α)·m2calib + α·needlefix`，α∈{0.20,0.35,0.50,0.65,0.80} | 若两能力在权重空间中**可分离**，直线路径上存在甜点 | 0 训练 + 扫描 |
| **R2** | `finetuning_type: freeze`，`freeze_trainable_layers: 4`（只训最后 4/28 层） | 把更新限制在输出侧，保住前段特征提取器 | 1 次训练 |
| **R3** | LoRA r=16/α=32 `lora_target: all` 后合并 | 低秩更新⇒扰动维度受限 | 1 次训练 |
| **R4** | 原混料但**降剂量**（0.5 epoch ≈180 步） | 侵蚀若与剂量成比例，则存在剂量甜点 | 1 次训练 |
| **R5** | **载体增广混料**：长上下文 3,724 + 契约 2,024 + **载体正向回放 6,000**（`data/lf/carrier_sft_slice.jsonl`） | 直接训练使命主轴（载体即数据）；门禁完整性已验（v0.3-gen 只含 image/av 元数据，训练中 0 次） | 1 次训练 |

**R1 的判读规则（可否证）**：
- 若存在 α 同时满足 A、B ⇒ **两能力在权重空间可分离**，零训练解决，且给出可复用的配方族结论。
- 若沿直线**单调此消彼长且无甜点** ⇒ **能力在权重上纠缠**（这本身是比"配方没调好"更强的结论），
  则 R2/R3（受限更新）成为唯一希望，并须写入 `docs/01 §7.1`。

### 9.3 预算与纪律

- 每个配方 ≤1 次训练（≤30 分钟）+ 2 次验收（needle ≈3.5 分钟、v0.3-gen ≈10 分钟）。
- **严格串行**：任何时刻一次只跑一个 GPU 作业（本项目已实测并发导致 10× 退化）。
- 每档都必须用**同一台仪器**（needle 64 次、v0.3-gen 168 条鲁棒性、`--prompt-format chat`）。
- **禁止**用 image_metadata / av_metadata 内容做训练（会污染 v0.3-gen 的"未见载体"主张）。
- 全部配方用尽仍无解 ⇒ **升级给用户**，附完整 (needle, ASR) Pareto 表与置信区间，不擅自改判据。

### 9.4 反例保护（什么会让我判定"搜索本身失败"）

- 若某配方 **needle 达标但契约跌破 63/168** ⇒ 不合格（契约是硬约束，不可交易）。
- 若某配方 **needle 达标、ASR 达标、但 PPL 显著劣于 m2-calib** ⇒ 不合格（G2）。
- 若**所有**配方的 ASR 都显著劣于起点 ⇒ 结论是"本架构/本数据下加法必然付泛化代价"，
  此时应改为**重新设计 M3 顺序**（把加法放到对齐之后），而不是继续调配方。
