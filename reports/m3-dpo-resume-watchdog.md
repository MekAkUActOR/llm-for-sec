### 1.1 lr 反推与调度地平线假设检验

调度：`lr(step) = 2e-6 · ½[1+cos(π·(step−60)/(T−60))]`（`cosine`、`warmup=60`、峰值 2.0e-6）。
对续跑段的每一个 logging 点，我把实测 lr **反解**成"哪个 step 会产生这个 lr"，并同时检验两个竞争假设：

| 假设 | 索引约定 | 与实测 lr 的最大相对误差 |
|---|---|---|
| **H1：调度地平线仍是 1803（正确续跑）** | step−1 | **8.12e-14**（机器精度） |
| H2：续跑后调度被重算成 1603 步 | step−1 | 3.02e+03（**被否**，差 1.4%） |

⇒ **实测 lr 逐点等于"1803 步余弦调度"在索引 (step−1) 处的值，相对误差 1e-16 量级**；
反解出的步号 = 204、209、
…、1799，即 **已经消耗了 200 步调度**。
这条同时证明了额外两件事：**(a) scheduler.pt 的 `last_epoch` 被正确恢复；(b) 步数地平线没有被缩短**——
后者是一个容易静默出错的续跑缺陷（若被重算成 1603，lr 曲线会整体偏快 1.4%，而 loss 曲线看不出来）。

> 注：反解步号比日志步号小 1，这是 HF `Trainer` 在 `lr_scheduler.step()` 之后才记录 lr 的固定偏置，
> 20 个点上是**恒定的 +1.00**（不是噪声），因此不影响任何结论。

### 2.5 ★ETA 的机制（为什么 `remaining_time` 在续跑后不准）与"排班建议"

LF 用"续跑后的 elapsed"除以"**全局** current_steps"去外推剩余时间——分母里带着 200 步的历史，
分子里没有，所以**续跑初期必然高估速度、低估剩余**；随运行推进两者收敛。

⇒ **排班不要用 `remaining_time`**，用 `(1803 − current_steps) × 实测步时` 自己算

### 3.6 ★`loss` 与 `accuracy` 的内部一致性（一条不需要额外数据的可证伪恒等式）

sigmoid DPO 的逐样本损失 `l_i = −log σ(m_i)`，`m_i = chosen_i − rejected_i`；被判反序的样本（`m_i ≤ 0`）
每个至少贡献 `log 2 = 0.6931`。而 `loss` 是该区间 **80 个样本**（5 步 × accum 16）的均值、`accuracy` 是其中
`m_i > 0` 的比例 ⇒ **`loss ≥ log2·(1 − accuracy)`** 必须成立。

实测：**360 个 logging 点全部成立，违反 0 次**。被判反序的样本数
（样本粒度）在最后 4 个点是 6, 4, 4, 5 / 80。

把 loss 下降拆开（前 20 点均值 → 后 20 点均值）：
`log2·(1−acc)` 项 **0.0962 → 0.0316**（翻转变少）
＋ 剩余项 **0.1800 → 0.0676**（正确样本的小间隔变宽）。

### 4.2 ★对父代理"早停规则在原理上无法检测抑制主导"的独立裁决

**结论：批评的结论成立，但机制描述需要改正，改正后的版本更强。**

**(a) margins 条对组成不敏感——成立。** `margins = rewards/chosen − rewards/rejected`，

+0.747，而 rejected 是 -10.817。**margins 无法区分"抬 chosen"与"压 rejected"。**

**(b) 但"margins 会机械地满足翻倍条件"只在'与起跑点比'的宽松读法下成立，而预注册写的是"同期"。**

| **严格（"同期"）：`margins(窗口末) ≥ 2 × margins(窗口首)`** | **2/356** | [5, 25] / [10, 30] |

严格读法下，25 步内翻倍只在最初的爬坡段可能（窗口起点 ≥ 10 后

又会在真正触发时更可能落在"正常爬坡"上（假阳）**。
这比"缺少判别力"更严重：它的触发区与病症区**不相交**。

**行为学命题**（"93–95% 的攻击成功根本没有裁决行"），而 §4.2 讨论的 acc/margins/chosen/rejected

后者只能由行为学门禁回答。这条必须写在替代方案的适用范围里（见下）。

### 4.3 组成感知的替代观测量（建议，不是改动）

**首选观测量：`C = mean(rewards/chosen)`（窗口均值，单位 nats×β）**，锚点天然存在——**0 就是冻结参考**。
"政策比自己的起点更不可能生成偏好回复"这件事不需要任何外部常数就能判读，且它是 DPO 已知的
"似然位移（likelihood displacement）"签名。

**次选（组成比例）：`λ_level = C / (C + |R|)`**，`R = mean(rewards/rejected)`。
λ=1 纯抬 chosen、λ=0.5 两侧等量、λ=0 纯压 rejected。本次数值：

| last_10_points | +0.871 | -12.211 | 0.0666 |

**⚠ 必须先说清 λ 的一个陷阱：端点差分版 λ 不可用。** 若按父代理最初写的
`λ = Δchosen/(Δchosen+|Δrejected|)`（端点差分），本次实测区间是 **[-40.50, 82.37]** ——
因为它是两个带噪差分量的比值，当两者都≈0 时会爆掉（"两侧同降"的窗口甚至给出 λ=−22）。
**要用就用窗口均值版 λ_level（centered-5 区间 -0.2028–0.9600，单调可读）**，


2. **该怎么定（推荐顺序）**：

### 7.1 ★纠正"stdout 里没有 rewards/*"（这条改变了监视方式）

上一任看门狗报告 §2 写"stdout（run.log）里一条 `rewards/` 都没有（我核对过，0 行）"——**这是错的**：

| 文件 | DPO 指标 dict 行数 | 覆盖步点 |
|---|---|---|

| `reports\logs\m3-dpo-run.log`（续跑，发射器 Tee） | 320 | [205, 1800] |
| `reports\logs\m3-dpo-resume-launch.log` | 320 | [205, 1800] |

每一行都是完整的 `{'loss':…, 'grad_norm':…, 'rewards/chosen':…, 'rewards/rejected':…,
'rewards/accuracies':…, 'rewards/margins':…, 'logps/chosen':…, 'logits/…':…}`。

**为什么上一任会看到 0 行**：Python 的 stdout 是**块缓冲（~8 KB）**，这些 dict 是成批 flush 的；
上一任在 13:26–13:29 读数时第一个 8 KB 还没 flush 出来（第一条 dict 出现在 launch.log 的
第 931 行，之前全是模型加载 INFO）。另外**被 kill 时缓冲区里的内容直接丢失**——这正好解释了
为什么"前一轮跑到 step 225，但 stdout 只有到 step 200 的 10 条"。

**对监视的实际后果**：`rewards/*` **有近实时通道**（`m3-dpo-run.log` / `m3-dpo-resume-launch.log`），
滞后只有一个 stdout 缓冲（实测 15–25 步 ≈ 50–85 s）⇒ **不必等每 100 步的 checkpoint**。

**我做了严格的交叉核对，而且它通过了**（`…-F-stdout-series.py`）：对
**360 个重叠步 × 5 个字段 = 1800 个数值**，
检验"stdout 是同一批数字的 **4 位有效数字渲染**"这一假设（判据 `|Δ| ≤ 半个末位`）：
**违反 0 个**。最大绝对差
（chosen 5.0e-04、rejected 5.0e-03、
margins 5.0e-03）**全部落在渲染精度之内** ⇒
**两条通道是同一批数字的两种写法**（不是两次独立计算）。stdout 可安全当实时尾巴用（4 位有效数字 ≈ 0.1%），
`log_history` 是权威值。

**另一个坑（我踩了）**：这三个日志是 **UTF-16LE（BOM `FF FE`）**——`Tee-Object` 在 PS 5.1 下的默认编码。
按 utf-8 读会得到 0 匹配（我的第一个解析脚本就是这么失败的）。必须 `path.read_bytes().decode("utf-16")`。
另外它们在训练期间被**独占写锁**（`[IO.File]::ReadAllBytes` 会抛 sharing violation），
但 Python `open()` / `Get-Content` 可读。

## §10 可复用协议草案：`chosen-below-reference` 事件段（可直接进 M4 预注册）

> 这是本报告唯一的**建议性**产出。它**没有**、也**不得**被用来改判 M3（父代理已在 §4.5 明确拒绝即时采用）。
> 它的价值在于：把"抑制主导/似然位移"从**事后叙述**变成一个**可以在下一次运行开始前就写死的观测协议**。

### 10.1 适用条件（不满足则协议无效，必须先声明）

- DPO 且参考模型**冻结**（起点权重的一份 `is_trainable=False` 副本，全程 `.eval()`）；
  `pref_loss=sigmoid`；每侧观测量都是**已减掉参考**的 `rewards/{chosen,rejected} = β·(logp_policy − logp_ref)`。
  ⇒ **0 就是"与自己的起点等价"这个绝对锚点**。若参考会移动（LoRA 参考、滑动平均、ORPO/SimPO），锚点消失，`C` 失去含义。
- `logging_steps` 固定；`trainer_state.json.log_history` 累积保存（本项目的 HF 行为，删除旧 checkpoint 不丢序列）。
- 若换了 β、换了数据配方或换了模型尺寸：**`C`/`λ` 的数值尺度会变**，阈值必须重标定（见 10.4）。

### 10.2 观测量

| 记号 | 定义 |
|---|---|
| `C_t` | 第 t 个 logging 点的 `rewards/chosen`（该点 80 个样本的均值，= β·(策略 − 冻结参考) 的 nats 数） |
| `R_t` | 同点的 `rewards/rejected` |
| `λ_t` | `C_t / (C_t + \|R_t\|)`：1 = 纯抬 chosen，0.5 = 两侧等量，0 = 纯压 rejected，**<0 = chosen 已跌破参考** |
| `Ĉ_t`、`R̂_t` | **centered-5 均值**（t−2 … t+2；序列两端用可用点并**标记窗口被截断**）。每点 80 样本 × 5 点 = 400 样本的平均，足以吸收"16 条随机 batch"的抽样噪声 |

**为什么必须用 centered 窗口而不能用逐点**：逐点 `C_t` 会被单个 batch 的组成拉动（本 run 逐点最负 −2.04，
而 centered-5 最负 −1.54）；窗口均值把"点噪声"与"段"分开。**不要用端点差分版本**
`λ = ΔC/(ΔC+|ΔR|)`：本次实测该量区间 [−40.5, +19.7]，两侧同降时爆掉（§4.3）。

### 10.3 事件段定义与"两侧同降"判据

1. **事件段** = `Ĉ_t < 0` 的**极大连续点列**（允许最后一段在报告生成时"进行中"）。
2. 对每一段记录：点数、步跨度、`min Ĉ` 及其位置、`min` 逐点原始 `C`、该段 `acc` 均值/`margins` 均值、
   以及 **`ΔC` 与 `ΔR`（段首到段尾的 centered 值差）**。
3. **"两侧同降"** ⟺ `ΔC < 0 且 ΔR < 0`。它是"整个回复分布的似然一起被推低"的直接签名，
   与"只压 rejected"（`ΔC ≈ 0, ΔR < 0`）和"正常分离"（`ΔC > 0, ΔR < 0`）互相排斥。
4. 该段的 `λ̂` = 段内 centered `λ` 的均值（或用段尾值）。

### 10.4 判据与**阈值锚定**（★本节的纪律核心）

**触发式（预警，非裁决）**：`事件段长度 ≥ k 个点` **且** `min Ĉ ≤ −D` **且** `λ̂ ≤ Λ`（或用"两侧同降"替代第三条）。

**`Λ / D / k` 三者必须在发射前写死，且不得由被监视的那一次运行确定。** 两条锚定路径（推荐顺序）：

1. **行为学锚定（首选）**：在**另一条**配方/种子/数据切片上做一次**刻意过训**的 DPO
   （目标步数的 2–3 倍，或更高 β，或故意剔除契约行），在多个 checkpoint 上**同时**测 `C/λ` **与行为学门禁**
   （MUST-B 契约保留率、MUST-A 的 ASR、误拒 ORR）。取"门禁开始劣化处的 `C`"，向下留边距（如该处 `C` 的 95% 下侧），
   并在至少一条**健康** run 上量出**假阳率**。`k` 由标定实验的假阳率/漏检率曲线选定，并在协议里声明
   `k ∈ (3, 5, 10)` 的敏感性（本 run 上 `k=3` 会触发、`k=5` 不触发 ⇒ **`k` 是有承重的参数，不能随便取**）。
2. **尺度无关的形状判据（次选，可预先声明）**：`C_rel = mean(C, 最近 k 点) / mean(C, warmup 后前 k 点)`；
   触发式 `C_rel ≤ 0.5 且 Ĉ ≤ 0`。0.5 是**形状常数**（不含 nats 绝对尺度，跨配方可迁移），
   而 `Ĉ ≤ 0` 是**参考锚定**的、有物理含义的条件。
3. **明确禁止**：用本次 M3 的读数反推阈值（如"平台 λ≈0.08 ⇒ 取 Λ=0.15"，或
   "**本次最长段的 λ̂ ≈ -0.12 ⇒ 取 Λ=0**"）。
   理由已在 §4.5 由父代理裁决定案；技术理由：M3 的**行为学门禁至今未跑**，我们**不知道**这个 λ 是否对应任何伤害，
   拿它定阈值就是结果驱动调参，会摧毁预注册 §6 的可否证性。
   **本次数据恰恰提供了这条禁令的反例教材**：协议在 step 490 之后"刚好"会响——
   若据此把 Λ 定为 0，那么在**任何**最终门禁结论出来之前，这条绊线就已经被本次运行的轨迹"训练"过了。

### 10.5 本协议在本次 M3 数据上的**全部**结论（仅供观察，不用于裁决）
