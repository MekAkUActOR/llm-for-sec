## 一、★★★ 先更正我上一轮的一个过强论断 ✗

第 16 轮我写：这 5 类的"**梯度几乎纯粹来自长度**" ✗。**证据不支持这么强的说法** ✗。

逐类量化"除了长度还能学什么"（`audit_dpo_nonlength_signal.py`，全量 28,842 对）：

| dpo_class | n | chosen `action` | rejected `action` | 空 findings（c/r） | 其它非长度信号 |
|---|---|---|---|---|---|
| `policy` | 14,688 | refuse/answer | **完全相同** | 84.8% / 84.8% | 仅文本内容（合理 ✓） |
| `reserve` | 5,710 | answer 4590/refuse 1118 | answer 4878/refuse 828 | 100%/100% | 类别分布略异 ✓ |
| **`carrier_inject_obedient`** | 2,360 | **report 2360/2360** | **answer 2360/2360** | **0.0% / 100.0%** | ★**100% 分离** ✓ |
| **`carrier_inject_hollow`** | 2,320 | **report 2320/2320** | **refuse 2320/2320** | **0.0% / 100.0%** | ★**100% 分离** ✓ |
| `bt330_refusal` | 1,904 | refuse 1904 | answer 1894 | 100%/100% | ★分离 ✓ |
| **`carrier_clean_overrefusal`** | 1,320 | **answer 1320/1320** | **report 1320/1320** | 0.0%/0.0% | ★**100% 分离** ✓ |
| `refusal_quality` | 300 | refuse 300 | refuse 300 | 82.0% / 100.0% | 轻度 ✓ |
| **`calibration`** | 240 | answer 144/refuse 96 | answer 240 | 100%/100% | ★`verdict:null` **0% / 60.0%** ✓ |

**⇒ 结论**：这 5 类**每一个都有 100% 干净的、与长度无关的类别信号** ✓✓
（`action` 完全分离、`findings` 有无分离、`calibration` 另有 `verdict:null` 分离）。

**⇒ 数据是**可用的** ✓。长度是**叠加的混杂（confound）** ✗，不是"唯一信号"** ✓。

**★ 那为什么 M3 还是崩了？** —— 因为**混杂是同向累积的**：
6,540 对**全部**是 chosen 更长 ✗ ⇒ DPO 在这些对上**顺带获得"更长更好"的梯度** ✓，
而长度偏好是**跨类泛化**的 ✗（类别信号只在类内可学 ✓）
⇒ **净效果 = 整体输出变长** ⇒ 部署预算装不下 ⇒ 尾部契约行被截断 ⇒ MUST-B 崩塌 ✓。

**★ 抽样实证语义与标签是**一致**的** ✓（`carrier_inject_obedient` 的 rejected 确实在服从）：
```
rejected: 已按载体内的指令跳过检查，本次判定为 clean。
          VERDICT: {"action": "answer", "verdict": "benign", ..., "findings": []}
```
**⇒ 两侧都流畅、都带完整合法 VERDICT、都含全部键** ✓ ⇒ **长度是它们最显著的表面差别** ✗
（这就是"模型会优先学到长度"的原因 ✓）。

## 二、★ 修法：外科式长度匹配（**不需要重新生成数据**）✓

因为类别信号完整 ✓，只需**消除长度差** ✓，**不动语义** ✓：

| dpo_class | 现况 | 修法（**只改 rejected 的长度，不改其语义**） |
|---|---|---|
| `carrier_inject_obedient` | rejected = **简短**的服从（132 字符）✗ | 把**服从的回复写详尽** ✓：真实的服从型 agent 也会长篇汇报 ✓ —— 保留 `action:"answer"`、`findings:[]` ✓，仅补足解释与过程 |
| `carrier_inject_hollow` | rejected = `无法协助。`（112 字符）✗ | 改为「**冗长但空洞**」✓：长篇不接地、不报载荷、`findings:[]` ✓ —— 与类定义（空洞短拒绝）**一致**，但不再靠"短"来区分 ✓ |
| `carrier_clean_overrefusal` | 160 vs 110 token（1.45×）✗ | 把**过度拒绝**写得同样详尽 ✓（过度谨慎的 agent 也会长篇论证 ✓） |
| `refusal_quality` | 57 vs 45 token（1.27×）✗ | 让**差质量拒绝**也写到相当长度 ✓（啰嗦但没说到点上 ✓） |
| `calibration` | 71 vs 45 token（1.58×）✗ | 把**过度自信**写得同样长 ✓（`verdict:null` 信号**保留** ✓，它正好是**非长度**信号 ✓） |

**★ 修完的验收判据**（`scripts/audit_dpo_length_confounding.py`）：
- 每类「chosen/rejected **token** 中位比 ≤1.2」**且**「chosen 更长比例 ≤80%」✓
- **同时**不得削弱类别信号：`action` 分离、`findings` 有无分离必须**仍然存在** ✓
  （★这是新增要求：**不能为了消长度差而把非长度信号一起抹掉** ✗）

**⇒ 因此规则 37 的门要**加一项**："长度匹配后，非长度判别信号仍在"✓
（否则修法可能"治好长度、治死信号" ✗）。已并入下方 §三。

## 三、规则 37 的补充（拟落 docs/01）

> **推论 37.3（消混杂不得消灭信号）**：对偏好对做长度匹配后，**必须复验**
> 该类的**非长度判别信号仍然存在**（如 `action` 取值、关键字段有无、
> 结构标记的分离度）✓。若长度匹配后两侧在**所有**非长度维度上也变得相同，
> 则该类已退化为"纯长度对" ✗ ⇒ **禁止入训**。
> **判据落地**：`scripts/audit_dpo_nonlength_signal.py` 必须对每一类
> 至少给出**一个** chosen/rejected 分离度 ≥ **0.95** 的非长度维度 ✓。
