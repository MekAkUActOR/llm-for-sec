### 2.3 T4 构念缺口（challenge/OOD 门主犯）

**读数（qa-report-v12.md，calib 推荐点主读数）**：**G2 T4 FPR 7.3333%（264 FP，距 <0.5% 门 14.7 倍）/ G3 挑战 T4 FPR 8.3983%（97 FP，距 <0.1% 门 84 倍）/ 挑战正例召回 345/345=100%**。FPR 仲裁记录：qa 双运行点交叉（run-v12-041243 vs run-v12-qaop-042708）**T4 FPR 两点完全相同 7.3333%——阈值无关的实现层证据**：FP 不是阈值放置伪影，是头的教义级存在性打分，无阈值可修。佐证构念方向（数据侧修复是唯一路径）。

- OOD 500 行 453 flag，**T4 占 450**——OOD 放过率 9.4% 失败 = T4 单头故事，**Mahalanobis 机制未失效**（弃权未触发是因 flag 先行）；
- T4 FP 子头：**100% span 驱动**（medical_id 197/person 128/dob 42/license_plate 38），68% 兼 doc 驱动（饱和 1.0）；正例侧 doc_score 全 1.0 + span 全 fire——**两个头学的都是"PII 存在性"**；
- **根因**：训练负例无 PII 密集良性 → 头按存在性打分；challenge/benign-heldout 文档天然含合法 PII（医疗研究日志）→ "存在性"构念无法区分泄露攻击文档与正当含 PII 良性文档。dev-mirror 1,100 对该人群零覆盖（校准池盲区）。
- **构念裁定（arch，本轮）**：**T4 = 语境条件检测——形式定实体性（人形 local=实体，服务/角色形=非实体），语境定极性（攻击/泄露语境→pos，合法语境→neg）**。实体类型恒 flag 政策否决（challenge 医疗文档含 medical_id，恒 flag 直接炸门）。
- **修法（数据侧）**：良性含 PII 负例（合法语境 PII 文档：医疗研究/授权工单人形收件人/HR 记录）进 T4 训练 + dev 校准（challenge-mirror 人群扩充）。RFC 5737 81 行案例收口即此构念的第一次适用（analyst@ 角色形 + 授权语境 → neg 释放）。
