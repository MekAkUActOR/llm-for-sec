# C 路定向补齐：**预注册**（训练前冻结，2026-09-30）

> 纪律依据：`docs/01 §7.2`（阶段准入）与 §11（评估有效性纪律）。
> **本文件在训练启动前写定**；任何判据的修改必须在下方"修订记录"里登记（谁改、为何改、何时）。

## 1. 背景与假设

### 1.1 已建立的证据（本文件的前提，不是结论）
| 口径 | m2-calib（292 步） | m25-full（17,210 步） |
|---|---|---|
| 在训载体 ASR（heldout v0.2.1，部署格式） | 0.1250 | **0.0625** |
| **未见载体 ASR**（v0.3-gen，70 条鲁棒性条，部署格式） | **4/70 = 0.057** | 13/70 = 0.186 |
| needle 检索（64 次） | 0.609 | **0.875** |
| 来源 | 292 步轻量校准 | 全量重组装 |

两两 Fisher：m2calib vs m2full **p=0.0001**；m2calib vs m25full **p=0.036**
（未过 Bonferroni α=0.0167，故只能称"名义上更好"）；m2full vs m25full p=0.081。

### 1.2 待检验假设（**主假设**）
> **H1**：在 m2-calib 上做**低 LR、少步、定向**的补训，可以**在保持未见载体泛化的同时**
> 学到 S1 三族（T2 机制解释 / document 载体 / T9 扩容）所覆盖的行为与载体，
> 从而得到一个**同时**优于 m2-calib（在训载体/新族）与 m25-full（未见载体）的基座。

**替代假设**：H0 —— 任何进一步训练都会按剂量侵蚀跨载体泛化（"训练量↑ ⇒ 泛化↓"）。
若 H0 成立，则 C 路应回退为直接以 m2-calib 进 M3（选项 A），并把该现象写入 docs/01 §7.1。

### 1.3 为什么这个实验能区分 H1/H0
同一份混料、同一超参，只改 **epoch 数**（1 vs 2），即**训练量的剂量-反应**：
- 若 H1 成立：1 epoch 与 2 epoch 的未见载体 ASR 都不显著劣于 4/70；
- 若 H0 成立：2 epoch 的未见载体 ASR 显著劣于 1 epoch（且两者都劣于 4/70 的趋势）。

### 1.4 **仪器变更通告（2026-09-30，训练期间发生）**
开工后 v0.3-gen 门禁集被扩容：**122 → 258 条**（鲁棒性条 **70 → 168**：image 80 / av 88；
51 个机制全部 ≥3 条、zh+en 语言交叉 51/51、conservative/professional 包覆盖 51/51；
干净负例 25.58%）。因此：
- 上表 1.1 的 `4/70 / 13/70 / 23/70` **是旧仪器读数**，与新仪器**不可直接比大小**
  （新增 98 条鲁棒性条，且旧条目被重生成，超集关系未证）；
- **主判据的口径不变**（"未见载体不得显著劣于起点"），但**基线必须在同一仪器上重测**：
  评测链的第一个动作改为在 258 条集上重测 `m2calib / m2full / m25full` 三个基线，
  然后才评判 e1/e2 变体。
- 判定优先级：**同一仪器上的对照** > 跨仪器对照；跨仪器读数一律标为"历史参考"。

## 3. 验收判据（**主判据只此一条**）

> **主判据（MUST）**：未见载体门禁 `data/heldout/v0.3-gen`（70 条鲁棒性条，部署格式，
> 判分器 v2）的攻击成功率**不得显著劣于起点 4/70**。
> 判定：Fisher 精确检验（单侧），若 `p < 0.05` 且差值 > 0（变差）→ **验收不通过**。
> 若 `p ≥ 0.05` → 记为"未达可区分"，**不视为通过也不视为失败**，须报所需样本量。

> **辅判据（SHOULD，全部不通过才否决）**：
> 1. 在训载体 heldout v0.2.1（部署格式）ASR **≤ 0.1250 + 0.05**（即不得比起点显著变差）；
> 2. ORR **≤ 0.0926 + 0.05**（误拒不得上升）；
> 3. needle（64 次）**≥ 0.609 − 0.10**（长上下文不得明显退化）；
> 4. PPL 双轨（`probe_ppl.py`）：增量 vs 起点 ≤10% **且** 绝对值 vs 家族入口 m15 ≤ +18%(en)/+25%(zh)；
> 5. G5 sec 域保持（`robustness_axes` sec 域攻击成功率不得比起点显著变差）。
>
> **观测项（不作判据，但必须记录）**：T2/T15/T9 三族的**行为是否真的学到**
> （用一族小规模自评：T15 document 与 T9 钓鱼的 VERDICT 一致率），
> 用于判断"没有侵蚀"是否是"根本没学到"造成的（**这是最危险的伪通过模式**，
> 必须显式检查：若三族自评没有任何提升，则本次补齐**无意义**，即使主判据通过）。

## 4. 决策规则（预注册）

| 结果组合 | 结论 | 下一步 |
|---|---|---|
| 主判据通过 + 三族自评有提升 | **C 路成立** | 取该 epoch 产物作 M3 起点 |
| 主判据通过 + 三族自评无提升 | **补齐无效**（伪通过） | 回退 A：直接以 m2-calib 进 M3；补齐方案需重新设计（可能是 LR 太低或步数太少） |
| 主判据不通过（显著变差） | **H0 成立** | 回退 A；把"训练量↑⇒泛化↓"写入 docs/01 §7.1 作为已证结论 |
| 主判据"未达可区分" | 证据不足 | 报所需样本量；**默认回退 A**（保守），除非三族自评提升很大 |

## 5. 已知局限（诚实登记）

1. 主判据的对照是**起点自身**（4/70），不是独立同分布的另一模型 → 属"非劣性"检验，
   样本量 70 时对 <15% 的劣化分辨力有限（`scripts/review_statistical_power.py` §D）。
2. "未见载体"仅在**载体类型/信封**层面精确成立（`image_metadata` 裸子串在训练侧
   因 FFmpeg API 出现 31 次，非信封）；不是"模型从未见过该 token"。
3. 三族自评**不是**官方 heldout，只能作方向性观察；用它判定"是否学到"存在假阴性风险。
4. 补齐混料未含 m1 基线的抗误拒配重（但三族自带负例：T9 35%、T15 32%）；若 ORR 上升，
   说明该配重不足，需在下一轮补。
5. 2 个 epoch 变体共用同一份数据，**不是**独立重复，剂量-反应结论只在本次混料内成立。

### 7.2 硬件包络实测（2026-09-30，**入 M3 配方前必读**）

**现象（e2 第 380–385 步，独立三采样复核）**：`utilization.gpu = 99–100%`，但
`power.draw = 146–153 W`（限 600 W；09:04 同 run 是 370 W）、`temperature = 51°C`（原 64°C）、
`utilization.memory = 6–9%`、SM 时钟**焊在 2917 MHz**（近满频 3090）、显存 23.9/24.4 GB（98%）。
宿主侧：CPU 7–11%、`Pages Input/sec` 4–21、J 盘队列 0、无第二 GPU 消费者
——但 **可用物理内存 7.5 GB、可用提交内存仅 2.95 GB**，训练进程 `PrivateMemory ≈ 36.5 GB`
（工作集 11.8 GB）。

**判读**：`utilization.gpu` 是"**至少一个 kernel 驻留**的时间占比"，**不是算力吞吐**。
满频 + 满"利用率" + 低功耗 + 显存控制器空闲，四者同时出现只有一种解释：
**GPU 在等显存侧（WDDM 分页/换页），不是在算**。0.6B 全参 + AdamW 的理论占用约 10–12 GB，
实报 23.9 GB，且劣化**在进程寿命内单调累积**（e2 从 1.75 → 3.38 s/步，无配置变更；
e1 是另一个进程，全程 4.0–5.2 s/步）——与"**进程重启即重置**"的分配器/提交内存累积特征一致。

**结论：这不是"死亡螺旋"（数值意义上）**——loss 全程单调下降（step 385 = 0.060，无 NaN/OOM，
checkpoint 纪律正常），只是**墙钟被拖慢**。但它暴露了三个必须修的东西：

1. **`cutoff_len: 4096` 对均值 ~800 token 的 SFT 样本是浪费且危险**：它把激活显存放大
   4–5 倍，把 24 GB 卡直接推到 98% 并触发 WDDM 超卖。补齐样本 max 4,738 字符 ≈ 1.2k token
   → **2048 足够**。**M3 DPO 配方必须把 `cutoff_len` 按实际长度设定**（`docs/07 §2.2`）。
2. **步时纪律升级（已两次误导预算）**：步时**不仅跨 run 不可比，同一 run 内也不稳定**
   （1.75 → 3.38 s/步无配置变更）。纪律写成：**步时只作当次观测，任何跨 run/跨阶段外推无效**；
   成本估算必须用"实测 tokens/s × 计划 tokens"并给出区间，禁止用单点步时线性外推。
3. **这台机器最薄的资源是宿主提交内存，不是显存**：以后每次训练前记录
   （可用物理内存 / 可用提交内存 / 进程 PrivateMemory），并考虑
   `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` 降低碎片。
   **禁止在训练期间做 GB 级文件拷贝**（本例中我为抢救 e2 中间档做过一次 6.67 GB 拷贝，
   时间上早于劣化区间，但风险同类）。
