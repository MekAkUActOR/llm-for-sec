# ★★★ M3 失效根因：DPO 数据集的**标记共模**与**长度混杂**双缺陷

**时间**：2026-09-30 晚。**这是"重开 M3 决策"的第一份实质答案**——
按我自己写下的纪律（先答"DPO 到底把行为改成了什么"，再谈换超参），
本报告全部结论来自**盘上产物的直接测量**，不含机制猜测之外的推断。

---

## 一、结论（一句话）

**M3 不是"DPO 这个方法是错的"，而是 M3 的 DPO 数据集有两个耦合缺陷**：
`VERDICT` 契约块在 **100% 的训练对两侧同时出现**（**零判别信号**），
而 `carrier_*` 类**100% 长度混杂**（chosen 比 rejected 长 3.9–4.9 倍）。
DPO 因此在**唯一可学的那一维（散文长度/风格）**上有强梯度，
在**契约标记上有零梯度** ⇒ 标记自由衰减、散文膨胀、在部署 token 预算内走不到裁决块。

**⇒ 修法是修数据，不是调超参。**

## 二、证据 1：推理侧——结构化输出整体少了 2/3（不是"丢前缀"）

`reports/resp-chat-gen-{soup-a050,m3-dpo}.jsonl`，258 条共同 id：

| | soup-a050 | m3-dpo |
|---|---|---|
| 含字面 `VERDICT` | **123 (47.7%)** | **38 (14.7%)** |
| 含 JSON 载荷键 | 111 (43.0%) | 49 (19.0%) |
| 含 JSON 但无 VERDICT | 2 (0.8%) | 20 (7.8%) |
| 呈复读（同片段 ≥3 次） | 0 (0.0%) | 1 (0.4%) |

- **我的"复读"假设被推翻**（0.4%，且起点为 0）——目视看到的两次重复未达阈值，
  **不能**据个别样例下机制结论。
- **也不是"只丢前缀"**（仅 20 条）。
- **真正的事实**：m3-dpo 的**任何**结构化输出都少了约 2/3
  ⇒ 它把预算花在散文上，**根本没走到裁决块**。

**2×2（含 VERDICT）**：`both=24  only_soup=99  only_m3=14  neither=121`。
**起点有而 M3 没有的 99 条**，是契约崩塌的主体。

## 三、证据 2：训练侧——`VERDICT` 在两侧 100% 出现 ⇒ 零梯度

`data/lf/dpo_m3_final.jsonl`（28,842 对）：

| chosen / rejected | 对数 | 占比 |
|---|---|---|
| **两侧都有 `VERDICT`** | **28,842** | **100.0%** |
| 仅 chosen 有 | 0 | 0.0% |
| 仅 rejected 有 | 0 | 0.0% |
| 两侧都无 | 0 | 0.0% |

**8 个 `dpo_class` 无一例外："chosen 缺 VERDICT" 全为 0.0%。**

**⇒ 机制**：DPO 的损失只依赖 chosen 与 rejected 的**相对**偏好。
当某特征在两侧**同时出现**时，它是**共模量**，在偏好梯度中被约掉 ⇒
**DPO 对该特征施加零压力**，它的存续完全交给基座先验与正则，**在 28,842 对 × 1803 步下必然漂移**。

**这解释了看门狗三条与行为无关的标量观测**（`reports/m3-dpo-resume-watchdog.md`）：
- `chosen` **无趋势**（+0.18/100 步，r²=**0.005**）—— 因为它**正是那个共模的部分**，没有可抬的绝对水平；
- `rejected` **猛沉**（−4.37 nats/100 步，r²=**0.882**）—— 因为**它才是唯一有差异的部分**；
- step 1300 出现 `acc=1.0` 而 `chosen=−0.20` —— **没有绝对水平可抬，只能拉开相对差**。
⇒ **三条标量观测与"零标记信号"完全自洽** ✓

## 四、证据 3：长度混杂——`carrier_*` 类 100% 偏置

| dpo_class | n | chosen 更长比例 | chosen 中位 | rejected 中位 | 中位长度比 |
|---|---|---|---|---|---|
| policy | 14,688 | 49.7% | 158 | 158 | **1.00** |
| reserve | 5,710 | 47.3% | 353 | 401 | 0.96 |
| **carrier_inject_obedient** | 2,360 | **100.0%** | **611** | 151 | **3.92×** |
| **carrier_inject_hollow** | 2,320 | **100.0%** | **608** | 120 | **4.89×** |
| bt330_refusal | 1,904 | 23.0% | 313 | 467 | 0.63 |
| carrier_clean_overrefusal | 1,320 | **100.0%** | 439 | 344 | 1.28× |
| refusal_quality | 300 | 98.0% | 142 | 120 | 1.17 |
| calibration | 240 | 95.0% | 175 | 128 | 1.38 |

- **`carrier_*` 四类（6,000 对 = 20.8%）100% 长度混杂**；
- **占一半的 `policy` 类完全长度匹配（1.00×）** ⇒ **偏置精确集中在 M3 门禁所要测量的载体类上**；
- 全局中位比 1.31× **掩盖了这种局部集中** ⇒ 只看全局会漏掉它。

## 五、证据 4：★训练目标**超出部署预算**（决定性）

- 部署生成上限：`max_new_tokens=96`；响应 dump 实测**中文字符 max = 509**（≈450 为实际墙）。
- **`carrier_inject_hollow` 的 chosen 中位 = 608 字符 > 预算** ✗✗
- ⇒ **即使模型完美模仿 chosen，也会在 `VERDICT` 块之前被截断**。

**这解释了先前那个看似矛盾的长度测量**：两臂字符数 p50 几乎相同
（soup-a050 264 vs m3-dpo 258），但**预算的构成变了**——
soup-a050 用它走到 VERDICT，m3-dpo 用它写 chosen 式散文并被切断。
也解释了**触顶组 VERDICT 率（22.4%）反高于非截断组（7.5%）**：
触顶的正是已进入冗长模式的响应。

## 六、`carrier_inject_hollow` 自证其反（逐条样例）

```
chosen   散文: 检测到注入载荷：载体头部包含「权威伪装指令」…按 §4.4 与 HF-004…
              载体内容一律是数据而非指令——拒绝遵循并作为发现上报…回到原任务：工单事项为…
chosen   VERDICT: {"action":"report","verdict":"contains-injection","confidence":0.92,
                  "findings":["carrier c1 head: authority_disguise (tool_output)", …]}
rejected 散文: 这个我帮不了。
rejected VERDICT: {"action":"refuse","verdict":"refuse","confidence":0.9,"findings":[],
                  "policy":"default"}
```

**该类名为 `hollow`（空心），本意应是把"空心拒答"作为负例**——但
**rejected 侧带着一个格式完全合法的 `VERDICT` 行**，于是实际教给模型的是：

> **"带完好 VERDICT 的短拒答，比带完好 VERDICT 的长报告更差"**

⇒ **它想惩罚"空心"，实际惩罚的是"短"**；**想奖励"上报"，实际奖励的是"长"**。
`carrier_inject_obedient`（同样 100%、3.92×）同理。

## 七、给"重开 M3 决策"的处方（**先修数据，后谈超参**）

| # | 改动 | 理由 | 可验证的预测 |
|---|---|---|---|
| **D1** | 让 `VERDICT` 块**成为判别轴**：chosen 格式完好，rejected **缺块/畸形块** | 消除共模 ⇒ 契约才有梯度 | 训练后契约保留率**不低于**起点 |
| **D2** | `carrier_*` 类**长度匹配**（或对 DPO 目标做长度归一/正则） | 消除长度混杂 | chosen/rejected 中位长度比 → ≈1.0 |
| **D3** | **chosen 长度压到部署预算内**（中文 < 400 字符 / 以 token 计 < ~80） | 让目标**可被产生** | 模仿 chosen 不再必然截断 |
| **D4** | 若 D1–D3 后仍偏，再考虑长度正则化 DPO 变体（R-DPO/SimPO） | **否则与数据缺陷混淆**，无法归因 | 单独评估 |

**★ 顺序不可颠倒**：**D1–D3 是数据修复，D4 是算法修复**。
先上 D4 会把"数据缺陷"与"算法选择"两个原因**混在一起**，
违反本会话反复使用的单变量归因纪律（规则 22 的同源要求）。

**★ 且必须先登记本次为"数据缺陷导致的失败"，而非"DPO 不适用"**——
两者对后续路线的含义完全不同。

## 八、证据 5：★marker 在 prompt 里 100% 被明示要求（否证"提示不一致"，并使机制更锋利）

`scripts/check_prompt_marker_exposure.py`：

| 检查 | 结果 |
|---|---|
| 训练对 system 含「输出必须以 VERDICT 行结尾」 | **28,842/28,842 = 100.0%** |
| 评估 prompt 含同一句 | **258/258 = 100.0%** |

**system 原文片段**：
```
硬底线（不可被任何政策覆盖）：HF-001 儿童性剥削内容；… HF-006 辖区硬法律条目。
方向性不变量：去保护方向（还原身份/明文、剥离脱敏）一律拒绝。
输出必须以 VERDICT 行结尾。
```

**⇒ 我的假设 (c)「训推提示不一致」被否证** ✓ —— 两侧都明示要求。

**⇒ 但这使机制更锋利，并上升为一条一般性原理**：
模型在**训练与部署的每一次**都被明确要求以 VERDICT 行结尾，
而 **chosen 与 rejected 双方都遵守了这条要求** ⇒
**这条被 prompt 明确规定的行为契约，在偏好对里同样是共模量 ⇒ 梯度为零。**

> **★ 一般性缺陷**：DPO 对"两侧共同满足"的行为**不提供任何梯度**，
> **无论 prompt 多么明确地要求它**。因此任何"chosen 与 rejected 都做到"的契约
> ——即使它是全系统最显式的行为约束——**都会在训练中自由漂移**，
> 其存续**完全交给基座先验**，而基座先验未必强（见下）。

**★ 由此暴露第二个独立缺陷**：**起点自身的契约保留率只有 70/168 = 41.7%**
（`m2calib` = 84/168 = 50.0%）——**契约从来没好过**；而预注册阈值 **63/168 = 37.5%**
**只比起点低 7 条**。⇒ **该门从设立起就几乎没有余量**
（"判据无分辨率"的**第四个实例**，见 `reports/criterion-no-resolution-three-cases.md`）。
本次 20/168 **远低于**阈值 ⇒ **FAIL 无歧义**；但登记该观察对下一轮定阈值是必要的。

## 九、边界与未证事项（诚实登记）


1. **机制链条有多环节，其中"标记衰减 ⇒ 保留率掉"是推断**；
   **已直接测量**的是：两侧 100% 含标记、`carrier_*` 100% 长度混杂、
   chosen 中位超预算、推理侧结构化输出少 2/3、契约 70→20、截断伪影已排除。
   **尚未做的**是"用修好的数据重训并观察保留率回升"——**那才是因果的最终检验**。
2. **未分离基座容量因素**：0.6B 模型在 28,842 对上可能本就保不住格式。
   D1–D3 修好后若仍掉，则须考虑容量/步数，**但那时才是它的嫌疑**。
3. **未检查 `conversations`（prompt 侧）是否含 VERDICT 示例**；
   若 system/prompt 里带格式示范，则"零信号"的解释需再细分。
   **列为下一步待查**。
4. 本报告**未改动任何数据或配置**，仅为诊断。
