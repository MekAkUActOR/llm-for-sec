## 0. 结论摘要

1. **现状盘点已复算**：C1-full = 1,087.8M token，其中通用回放 60.06%（en 48.63% + zh 11.43%）、
   安全域 39.94%（唯一 217.23M ×2 epoch）。zh 合计 **12.44%**，ai_safety **≈0%**、
   privacy **0.013%**、code **0%** —— 与 `review` §4.3 的数字**逐位吻合**（§1.2）。
2. **重设的核心不是"加量"而是"换结构"**：安全域在 C1 的边际剂量已被证明极低
   （唯一文本 72M → 434M 曝光，×6，sec PPL 只从 −17.4% 走到 −19.0%，`review` §2.1）；
   因此 C1.1 把安全域**从 39.94% 降到 28%**，把腾出的份额给
   **ai_safety 10% / privacy 4% / code 8% / 载体结构层 2% / zh 26%**。
3. **16 行 manifest 疑点已逐一核对**（§4）：盘上 1,166.5 MB 对应 **280.25M token**
   （非 0），但它们的 `domain` 全是 `sft`——**是 SFT 原料层，不是预训练供给**；
   其中 `wildjailbreak` 97.6M / `wildguardmix` 44.4M 两项就占一半。
   它们能否按 `docs/01 §3.1` 的"AI Safety 层：越狱/注入研究语料、红队对话"进入 C1.1，
   受 **uplift 红线**（`docs/04 §0`）与 **CC-BY-NC 许可**双重约束（§3.4、§6-①）。
4. **最大缺口不是 token 量而是三件缺的东西**：zh 安全域（缺 42.5M，采购通道已被
   `docs/04 §5.1` 判死）、privacy 规模层（缺 46.9M，摘要层物理上限 ~5M）、
   载体结构/行为层（缺 24M，现存 0）。三者都只能靠**合成 + 序列化器批量产出**（§3.4）。
5. **一条必须先修的仪器缺口**：**目前没有任何机械断言把预训练混料与
   `data/heldout/v0.2.1` / `v0.3-gen` 对上**（§1.4）。C1.1 任何变体在发射前必须补这一步，
   否则升级全量重训就是第二次"用被训练覆盖过的载体证明未见载体泛化"
   （`review` §4.4）。

### 2.2 逐条理由（全部回溯既有文档，不凭直觉）

**(1) general_en 26%**——`docs/01 §3.1` 表"通用维持 30–50%，防灾难性遗忘"是**上限纪律**，
不是目标值；`docs/04 §2` 的设计值是 35%（zh:en≈1:1 时 en 侧 ≈17.5%）。
C1 的 48.63% 把通用回放做成了主语料（60.06%，超上限），而 `docs/01 §1.1` 明确基座是
**安全感知**基座、通用能力是"防遗忘"手段。取 26%：
① 高于 `docs/04 §2` 的通用总设计（35%）在 en 侧的等价份额，留出安全回旋；
② 使"通用总占比"回到 48%、落在 30–50% 带内；
③ 通用池 714.9M 对 312M 的需求有 2.3× 冗余 ⇒ 可用**质量过滤**而非全量直用（质量换体积）。

**(2) general_zh 22%**——D2"中英双语，政策条件化双辖区"（`docs/00 §12` D2；`docs/01 §4`）；
`docs/04 §2` 的 zh:en≈4:6 是原设计，`docs/04 §5.1` 实测"中文语料实测盘点 zh 共 ~130M token"
并明确"不硬凑 4:6"。S3 已批准 zh ≥25%（`docs/01 §12-2`）。取 22% + 安全/隐私 zh 4% = **26%**：
① 满足 S3 硬下限并留 1pp 余量；② 物理供给充足（zhwiki 全量 ≈830M，仅需 264M = 32% 采样率，
比现行 15% 翻一倍，纯 CPU 重采样可完成，`docs/04 §5.1` 已实测采样率可调）；
③ 22% 而非 25% 是因为 zh 侧**安全域**天然稀缺（5.5M），若把 zh 全压在通用 wikipedia 上，
等于用一个百科域冒充"双语安全能力"——真正的双语安全能力缺口单列在 (4)。

**(3) security_en 24%**——D6"AI Safety、Security、Privacy 优先"（`docs/00 §12` D6；
`docs/01 §4.1` Security 为第二优先）。**从安全域合计 39.94%（其中 en 38.87%）降到 28%（en 24%）
是本方案最反直觉的一步**，理由是
实测的剂量-响应曲线已饱和：`review` §2.1 记 C1-202M 的有效安全知识针 8.6M 把 sec PPL
从 −17.4% 推到 −19.0%，而 C1-full 把唯一安全文本从 72M 扩到 434M 曝光（×6）**只换来 −1.6pp**，
且仍差硬门禁（≥25%）6pp（`docs/05:121`、`docs/01 §7.1` M1 行）。
继续加同一批**摘要层**文本不是解——`docs/04 §4` 的 C2 结论已把摘要层的物理天花板写死。
所以 C1.1 对 security 的策略是**保持绝对量、提高多样性、把总量份额让给缺域**：
24% × 1.2B = 288M ≈ 与 C1 的 434M 曝光相比仍下降，但**多样性上限**同时施加：
单源 ≤20%（`docs/05 §8` "NVD 类单源占比上限 20%，多样化采样"）→ redhat 对 288M 的
份额必须从 38.26% 压到 ≤20%（≈57.6M），差额由 t6 补丁 diff、厂商通告、
CTI/事件复盘（许可逐源核验）、p0-0days 类补足。

**(4) security_zh 4%**——`docs/01 §3.1` 单列"中文专项"层（中文法规、中文安全社区、
反诈/钓鱼语料），备注就是"平衡 D2 双语"。现状 5.5M 是**结构性缺口**：
本项 4% × 1.2B = 48M 是让"中文安全能力"从"只有 wikipedia 安全分类树"变成
"有可训练剂量"的最低要求。取证见 §3.4（采购通道已判死 → 必须合成）。

**(5) ai_safety 10%**——D6 **第一优先**域（`docs/00 §12` D6），`docs/01 §3.1` 表中
AI Safety 列在首行且备注"与 Stage 4 形成反身协同（§4.1）"。`docs/04 §2` 设计 10%。
C1 实际 ≈0%（`review` §4.3），"全靠 M1.5 的 8.6M 有效知识针承担 → 剂量-响应不足"（同处）。
取 10% 即**回到设计值**，无新论证负担。

**(6) privacy 4%**——D6 第三优先；`docs/01 §3.1` Privacy 层"双辖区并重"；
`docs/04 §2` 设计 5%。取 4%（略低于设计）的唯一理由是**供给现实**：
`docs/04 §4` 实测"隐私域摘要层物理上限 ~5M，远低于 20–50M 目标"，5% × 1.2B = 60M
需要 12× 的供给扩张。4% 是"在不伪造数据的前提下"的诚实目标，并强制 §3.4 的合成线立项。

**(7) code 8%**——D5"文本 + 代码（网页以 DOM 文本纳入）"（`docs/00 §12` D5；`docs/01 §2.4`）；
`docs/04 §1` P2 表把代码类语料列为 SFT 判断对象、`docs/04 §2` 设计 code 15%。
S3 批准区间 **5–10%**（`docs/01 §12-2`）。取 8%（区间中上）因为 code 在 C1 是 **0%**，
而 `review` §4.2 判定"代码迟到"是明确的覆盖缺口；不取 10% 上限是因为
`docs/04 §0` 的 uplift 红线（"武器化内容不进 Stage 1"）会砍掉 The Stack 类语料中的
恶意代码子集，实际可入训比例低于采购比例。

**(8) 载体结构层 2%**——`docs/01 §2.4` 把"载体序列化格式"定为**一等工件**
（"格式是模型契约的一部分，改格式必须重训/继续训"），`docs/00 §3` 的核心论据是
"载荷常居语义之外（五栖居处）"。而 `review` §4.2 实测：**document 载体 = 0**
（`secfm/carriers/base.py:60` 的 `_CARRIER_TYPES` 无 `document`）、
**结构层/行为层基本空白**。同时 `review` §4.4 已判定 tool_output 留出族被 t14 覆盖，
"未见载体泛化"处于无证据状态——**这正是因为预训练从未见过载体序列化文体的分布**。
2% × 1.2B = 24M 是把 `<carrier type=… trust=…><meta>…</meta><body>…</body></carrier>`
文体从"只在 SFT 里见过几千行"提升为"预训练期见过的文体"的最低剂量。

## 4. 16 行 `est_tokens=0` 的逐一核对

### 4.1 测量方法（可复算）

工具：`scripts/estimate_corpus_tokens.py`（本次新建，**只读**）。
命令与种子：

```powershell
.\.venv\Scripts\python.exe scripts\estimate_corpus_tokens.py --hash-duplicates `
    --out reports\corpus-token-estimate.json        # seed=20260930, 每文件蓄水池抽样 k=200
```

- **记录口径**：一条记录（JSONL 行 / CSV·TSV 行 / JSON list 元素 / parquet 行）里
  **全部字符串叶子**用 `\n` 连接（写死在 `record_text()`，换口径须改工具版本号）；
- **token 计数**：Qwen3-0.6B-Base `tokenizer.json`（`tokenizers` 后端，
  `add_special_tokens=False`），纯 CPU，不加载权重；
- **外推**：`T̂ = N_reco × mean(tokens/reco)`；
  95% CI = `T̂ ± 1.96·(s/√k)·N`，`N>k` 时乘无放回有限总体校正 `√((N−k)/(N−1))`；
- **不确定性的边界**：CI 只覆盖"同一文件内记录间"的抽样方差，
  **不含**字段口径与格式解析误差；
- **量纲核对**：工具同时输出记录数，与本 manifest 的 `docs` 字段比对（§4.4）。
