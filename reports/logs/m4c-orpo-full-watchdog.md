## 1. Schema dump（先核后析，绝不猜）

log_history 每条记录的全部键（15 个，360 条同构，无 eval 条目——日志明示 "No metric eval_loss to plot"，eval_steps=500 但未配 eval 集）：

```
step, epoch, grad_norm, learning_rate, loss, sft_loss, odds_ratio_loss,
logps/chosen, logps/rejected, logits/chosen, logits/rejected,
rewards/chosen, rewards/rejected, rewards/margins, rewards/accuracies
```

**恒等式全量数值验证**（360 条，最大偏差）：

| 恒等式 | 最大偏差 | 含义 |
|---|---|---|
| `sft_loss = −logps/chosen` | **0（精确）** | sft_loss 即 chosen 的每 token NLL（长度归一化） |
| `loss = sft_loss + 0.1×odds_ratio_loss` | 3.6e-07 | ORPO 损失结构确认（sft 锚权重 1.0，β=0.1） |
| `rewards/chosen = 0.1×logps/chosen` | 3.0e-08 | rewards/* 是 β 缩放的**策略自身** logps |
| `rewards/rejected = 0.1×logps/rejected` | 5.1e-08 | 同上，非参考相对 |

⇒ **无参考模型；logps 为长度归一化每 token 均值（trainer.py L234-235）** ⇒ sigmoid 对照的「rewards/chosen ≥ +1」判据口径作废（预注册 §四② 已声明），本报告判据 = **chosen 侧 NLL（sft_loss）有界性 / 单调性**。

## 3. 塌缩前兆判定（预注册 §四②：chosen 侧单调恶化且无界）

**判定：未触发。** 证据：

1. 分箱均值 9 箱 **8 降 1 升**，唯一上升箱（801–1000 → 1001–1200，+0.018）随后连续两箱回落至全程最低 0.2604——是平台期噪声，非趋势反转；
2. 最长连续上升段仅 4 条记录（step 375→395，幅度 <0.1），其后即回落；
3. 全程最大值出现在 step 5（训练起点 2.5116）；warmup 后（step ≥200）逐箱最大值 ≤0.74，step ≥500 后 ≤0.46——**严格有界**；
4. 末值 0.2617 仅为起点的 10.4%。方向与「恶化」相反。

sigmoid 对照（M4-capfix-full）在同一坐标上的形状：chosen 分箱 +1.93 → +0.35 → +0.90 → +1.37 → **−0.91 → −1.99 → −5.09** → −3.73 → −3.15，末点 −3.63——step ~800 断裂后单调塌缩、无恢复。**M4c 全程无此断裂点**：801–1000 箱 sft_loss 0.2704，恰为对照发生断裂的位置，本实验稳定且续降至 0.2604。

## 4. 与 sigmoid 对照（M4-capfix-full）解读

- **死因回顾**：sigmoid DPO 无 chosen 锚，靠 rejected 压制拉开 margin——win-rate ~0.95 的同时 chosen 被拖到参考模型下 36.3 nats（序列求和口径），MUST-B 契约保留崩至 100/168。
- **本实验**：chosen 每 token NLL 从 2.51 降至 0.26（似然上升 ~9.5 倍），方向与塌缩**相反**；margin 增长（0.98 → 2.18 nats/token）**主要来自 chosen 侧改善（−2.25 nats），rejected 侧仅 +0.37 nats**——与 sigmoid 的「rejected 单侧压制」机制形成干净对照。这正是 sft 锚（sft_loss = −chosen_logps，权重 1.0）的设计预期：**预注册假设「ORPO 的 SFT 分量防止 chosen 塌缩」在训练侧指标上获得支持**。
- 训练侧健康指标同向：accuracies bin 均值 0.84–0.92（末段 0.91–0.94）、odds_ratio_loss 0.36→0.14 下降、grad_norm 无发散。
- **注意**：sigmoid 对照的 train accuracies（0.92–0.96）数值上更高——那是 rejected 压制换来的；ORPO 的 0.91 略低但双侧健康。**不能用准确率数值高低评优劣**（对照组看门狗已证明高 win-rate 可与病态并存）。
- 运行时长旁证：1:04:59 vs 对照 1:25:58（−24%），符合无参考模型、每步一次前向的结构差异。

## 5. 诚实告警（判据边界，逐条声明）

1. **logps 尺度不可比**：ORPO 的 logps 为长度归一化每 token 均值（trainer.py L234-235），sigmoid 的 rewards 为序列求和且参考相对（对照末期 logps/chosen ≈ −374 nats 序列和 vs 本实验 −0.26 nats/token）。**两侧数值不可直接对比，本报告只做方向性/形状对照**。
2. **无参考模型 ⇒ 无 KL 锚**：rewards/* 仅为 0.1×策略 logps（恒等式已验证），不是优势估计；「sigmoid 的 rewards/chosen ≥ +1 作废」是口径问题，**不构成 ORPO 更优的证据**。
3. **对照组绝对塌缩的每 token 量级未量化**：−3.626（β 缩放序列求和）在未知响应 token 数下无法换算为每 token NLL，故**不能**宣称「0.26 vs −3.63」这类量化对比，只能说一侧升一侧降、形状相反。
4. **无 eval 集**：sft_loss 是训练集口径，chosen NLL 的 held-out 泛化未验证；且训练末段 NLL 低至 0.15–0.26，**训练集上 chosen 的过拟合/记忆无法从这些曲线排除**。下游质量（MUST-B 契约保留等）由正在运行的门禁评测（gate_m4_full.ps1 -FullTag m4c-orpo-full）裁决，**本报告不含下游结论**。
5. **rejected 侧压制温和（+0.37 nats/token）**：若门禁出现模式坍缩/风格单一化以外的失败（如安全性拒答不足、坏格式仍出现），需回看 odds 权重（β=0.1）是否过弱——训练侧指标无法排除这一点。
6. **accuracies 口径差异**：此处为长度归一化策略 logps 的 chosen>rejected 比较（无参考相对），且为 5 步窗口均值（batch=1），单点波动大（0.60–0.99），不宜与 DPO 准确率直接对比。
7. **grad_norm 中段偏高**（bin 均值 3.5–10，末期 ~3.0）：无发散/NaN、趋势下降，仅作观察记录。
8. **看门狗时点如实记录**：01:34–01:37 完成基线交互检查（GPU 13.4 GB 占用、step 170、sft 0.95–1.03）；原定 01:54 / 02:15 两次定时检查因后台作业被系统注册表回收（pwsh-2420 → unknown job，输出不可得 = 无证据）**未送达**，报告不虚构这两个时点的读数。数据完整性由 360 条全量 log_history + 19 个 checkpoint 时间戳（间隔均匀 3:34–3:45/100 步 ≈ 2.14–2.25 s/it，无中断缺口）客观补全。

## 结论

M4c-ORPO-full 1,803 步全程跑完（rc=0，无中断）。**chosen 侧 NLL（sft_loss，长度归一化口径）2.51 → 0.26，严格有界、整体单调改善，预注册 §四② 的「塌缩前兆」未触发**；margin 由 chosen 侧改善主导（rejected 仅 +0.37 nats/token），与 sigmoid 对照的 rejected 单侧压制 + chosen 塌缩（末值 −3.63，step ~800 断裂无恢复）形成方向相反的干净对照。**SFT 锚防塌缩假设在训练侧指标上成立**；下游 MUST-B 等质量结论待门禁评测，不在本报告范围。
