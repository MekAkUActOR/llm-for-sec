## 四、★A2 阻断项根因（fail-closed 门的第一笔真实拦截 ✓✓）

`check_p16_calibration.py` 复跑 = **G1 FAIL（其余 G2–G12 全 PASS）**：G1 的防重叠字节扫描范围含 `data/dpo/**/*.jsonl`，而 P2.9 把 M5 物化件放在 **`data/dpo/m5/dpo_m5_calib.jsonl`** —— 该件**按设计理应包含全部 5,760 个 p16 id**，于是被 G1 判为「既有混料中出现 p16 id 格式字面量 5,760 处」（扫描 62 文件 / 8.02GB；此前 PASS 时 61 文件 / 0 命中）。**这不是数据质量问题**（A1/A3/A4 已证混料逐 id、逐分布、逐 sha 闭合），而是**接线位置冲突**：p1.6 设计 §4.5 指定的落点 `data/m5-run/` 在 G1 扫描范围**之外**（设计如此是有意的 ✓），P2.9 实际落点在范围**之内**。发射链在 G1 与 P2.9 之间**死锁**，须所有者裁决：

- **选项 ①（设计归位）**：物化件迁移至 `data/m5-run/dpo_m5_calib.jsonl`（§4.5 原设计落点）——但 P2.9 的 manifest/dataset_info/config 接线须按版本纪律重开目录，改动较大 ✗。
- **选项 ②（检查器侧豁免）**：`check_p16_calibration.py` G1 扫描范围排除**被批准的 M5 集成落点**（`data/dpo/m5/`）——G1 意图是「p16 id 与**先于 p16 的既有**混料零交」（防重复/污染），M5 集成件是**被批准的后继者**，豁免不违背意图 ✓；但需登记豁免并重跑门禁。
- 无论选哪个：修复后重跑 `launch_audit.py --tag m5`，A2 转 PASS 即 `LAUNCH-AUDIT=PASS`（其余四检已全绿）。
- **登记**：本审计三次复跑（虚拟并集 1 次 + 物化 2 次，A2 各跑一遍检查器）结果稳定（G1 5,760 命中不变）；`reports/p1.6-gate-report.md` 已被复跑覆写为 FAIL（G1 单项）——这是检查器的正常落盘行为，G2–G12 仍全 PASS ✓。
