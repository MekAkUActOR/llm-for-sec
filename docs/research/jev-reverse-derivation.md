## 0. 推导的出发点：事实 → 约束

| # | 可观测事实 | 推出的约束 |
|---|---|---|
| F1 | 输出只有三种原语；结构化错误率 0%（"数学保证"） | 输出路径上无任何生成式组件；输出 = 固定形状张量上的确定性算术 |
| F2 | Score 示例：probabilities {0: 0, 1: 0.96, 2: 0.04} → score 1.04，精确等于 1×0.96+2×0.04 | Score 不是回归头，是**档位分布的期望值**；三种原语可统一为一种 readout |
| F3 | 官方：confidence 是"从分布形状算出的统计量"、"大多数场景够用的默认定义" | confidence 是后置派生（max-p / margin / 负熵族），不是独立模型输出 |
| F4 | 多问题并行；官方：与单独提问**答案完全一致**；加问题只增加输入 token | 问题之间零注意力交互；state 表示不依赖问题内容 |
| F5 | API 把 state 与 questions 设为两个字段；单请求 ~32K token 共享预算 | 计算结构 = 共享前缀（state）+ 轻量分支（问题）；一切序列化进一个上下文窗 |
| F6 | Choice 上限 255 个选项 | 候选被序列化/批分支，上限是 serving 张量维度与 token 预算约束，非能力约束 |
| F7 | 70–500ms 端到端；输入 $0.042/M、输出免费；"并行采样" | 无 decode（输出免费的字面原因：没有输出 token）；prefill-only、compute-bound；骨干亚十亿级 |
| F8 | 跨领域泛化；任意用户自定义 instructions/criteria | 无任务专用头；候选是自然语言描述 → 语义匹配式打分；"回答类型化问题"是被训练的**元技能** |
| F9 | Diogo："预训练把互联网知识压缩成智能核心，问题是怎么释放" | 从预训练骨干出发改造输出侧，不从零训判别器 |
| F10 | 训练目标为校准（RLCD）；官方用随机 ID 插入测语义稳定性 | 损失含真值评分规则；训练数据含不变性增强 |

| F12 | 官方建议：Score 档位写情形不写程度（纯程度词输出不稳）；Choice 必须留"其他" | 档位/候选是**独立打分**的语义锚点；闭集 softmax 无法表达"都不对" |

## 1. 模型结构推导

### 1.1 先排除三个候选方案

**假设 A：小 LLM + 约束解码**（在选项 token 上做受限生成）。
排除：受限解码仍要逐 token decode；255 选项 Choice 需解码多个 token，延迟会随输出长度增长——与"问 1 个和问 10 个问题延迟几乎不变"（F4/F7）矛盾；且无法一次给出全分布（要么 255 次 forward，要么退化为单标签）。

**假设 B：言语化置信度**（RLCR 用于推理模型的方式：模型"说出"90% 置信）。
排除：Jev 无文本输出（F1）；概率必须是精确实数。

**假设 C：固定分类器集群 + 路由器**。
排除：用户在推理时动态定义任意选项与措辞（F8），无法路由到固定类别头；跨领域泛化也无法用分类器堆解释。

### 1.2 输出侧：三种原语统一为一种 readout

F2 的算术是决定性证据。设每个问题有 K 个候选（Noul: K=2；Choice: K=选项数；Score: K=档数）：

```
logit_k = w · h(anchor_k)          # 共享标量打分头；anchor_k = 候选 k 的表示
p = softmax({logit_k})              # 每问题恰好一个 categorical 分布

# API 层的确定性派生（纯算术，非模型输出）：
noul      = p[yes]                  # K=2 特例
choice    = argmax_k p  +  p        # 完整分布
score     = Σ_k k · p_k             # 期望值 → 1.04 这类非整数自然涌现
confidence = g(p)                   # 分布形状统计量（max-p / top1−top2 / 负熵族）
```

推论链：

1. **Score 无独立回归头**（CSDN 文章的"sigmoid 回归头"说法与 F2 矛盾）。非整数分数是期望的算术结果。
2. **Noul 无 confidence 字段的原因**：K=2 时分布只有一个自由度，p=0.95 本身就完整描述了肯定程度（离 0.5 多远）；再加 confidence 是冗余。K>2 时 max-p 不能单独刻画分布形状（三项近均分 vs 一项 0.6 其余分散，max-p 相同但不确定性迥异），才需要派生统计量。这是"单一分布 readout"假说的自洽性验证。
3. **结构错误率 0% 的来源**：输出是闭集张量上的确定性算术，物理上不存在"格式错误"的代码路径。
4. **闭集softmax 解释 F12**：分布必须在你给的选项上归一——模型没有"都不对"的表达通道，所以官方要求 Choice 留"其他"选项。

### 1.3 输入侧：一切序列化 + anchor 位置

```
[SOS] <state> …state tokens… </state>
<q1> …instructions tokens…
     <cand> 选项1描述 </cand> <cand> 选项2描述 </cand> …
</q1>
<q2> …
```

- `<cand>` 等特殊标记是可学习的 anchor embedding，readout 在这些位置取表示（F5/F6 的序列化约束）。
- 32K 预算由 state + 全部问题 + 全部候选共享（F5）——进一步证明它们在同一条序列/同一次批处理里。
- 255 上限（F6）：serving 的分支张量维度上限；有效上限其实是 token 预算（255 个候选 × 每个数十 token 早就超 32K）。

### 1.4 注意力结构：共享前缀 + 问题分支

F4（"与单独提问答案完全一致"）是强约束：问题分支之间必须无注意力交互，且 state 的表示必须与问题内容无关（否则不同问题组合会互相污染）。满足方式有两种等价变体：

**变体 A：decoder 骨干 + 前缀 KV 缓存（候选独立打分）**
- state（+问题指令）作为前缀，因果掩码，KV 只算一次；
- 每个（问题, 候选）作为轻量后缀分支，对前缀做注意力，**候选之间不互见**；
- 互斥性完全由 readout 的 softmax 提供。

**变体 B：分段双向掩码（候选间集合注意力，NanoJev 的选择）**
- 同一问题的候选块内双向，模型显式理解"互斥选项集"。

**证据裁决：倾向变体 A。** F12 的官方失败案例——Score 档位写成纯程度词（"中等严重"）时输出 0.57、置信度 0.35、判断不稳——说明每个档位描述必须**独立携带语义锚点**才能被打分。若候选间有集合注意力，模型本可利用档位间的相对结构补偿弱锚点。独立打分（A）则完全依赖每个候选自身与 state 的语义匹配。Simple Jev 用"共享前缀 KV + 读候选 logits"复现出官方行为模式，jev-forge 的定位语"score dynamic candidate **branches** from a shared prefix"也字面指向 A。

**state/questions 的字段分离（F5）就是变体 A 计算结构的 API 投影**：state 算一次、问题分支近乎免费。若不共享计算，接口只需一个 prompt 字段。

### 1.5 骨干规模与 serving

- 规模推导：Raschka 猜 ModernBERT 级（base 149M / large 395M）；open-jev 复现用 150M 达到自报 0.697（Jev 0.727）；NanoJev 用 600M 达导航 95/90（Jev 100/95）。综合：**约 150M–600M**。
- 70–500ms 端到端（含网络/排队）与亚十亿模型 32K prefill 的算力开销自洽（F7）。
- $0.042/M 输入价 = 亚十亿模型 + 无 decode + 高批利用率的叠加；**输出免费不是定价策略，是没有输出 token 可计价**。
- 32K 上下文对小骨干意味着需要长上下文处理（RoPE 外推/调整类训练）——一个次要但真实的工程要求。

### 1.6 完整结构（推导版）

```
                ┌──────────────────────────────────────────┐
 state ─────────►│ 预训练 Transformer 骨干（~150M–600M）        │
 (算一次,缓存)   │  · 无 lm_head                              │
                │  · 注意力：state 前缀 ↔ 问题分支单向；        │
                │    分支间零交互；候选独立打分（变体 A）        │
                └───────────────┬──────────────────────────┘
                                │ 各 <cand> anchor 的隐藏表示
                                ▼
                ┌──────────────────────────────────────────┐
                │ 共享标量打分头 w·h → 每候选一个 logit        │
                │ 每问题 softmax → 一个 categorical 分布      │
                └───────────────┬──────────────────────────┘
                                │ 确定性算术
                                ▼
        noul = p[yes] · choice = argmax+p · score = Σk·p_k · confidence = g(p)
```

**这个结构逐条解释官方 API 设计**：字段分离=前缀共享；问题并行=分支独立；输出免费=无 decode；结构零错误=闭集算术；加问题近零成本=分支近乎免费；255 上限=批维度。

## 2. 训练方式推导

### 2.1 先问对问题：哪里真的需要 RL

关键认识：**对有真值标签的单步决策，真值评分规则损失（交叉熵/Brier）的监督学习已经给出校准的最优解**——proper scoring rule 的最优策略就是真实条件分布，梯度下降即可，不需要 RL。那 RLCD 的"RL"从哪里获得必要性？只有三处监督学习供给不了的信号：

1. **无标签、有结果**的数据：路由决定事后被纠正/接受、邮件被回复/忽略、审核被申诉/维持——延迟的环境反馈；
2. **多步情景数据**：一个决策的价值取决于后续（agent 轨迹），需要跨回合 credit assignment；
3. **非二值的可验证奖励**：RLVR 的"可验证"升级——奖励不是 0/1 正确性，而是**按校准度打分的可验证信号**（RLCR 构造）。

由此推出训练必然是**分阶段混合**，而非单一算法：

### 2.2 四阶段流水线

**阶段 0：骨干继承。** 预训练 LM 直接拿来（F9），语言理解、JSON 解析、指令语义全靠它——这也解释了为何不可能从零训：跨领域泛化的世界知识只能来自预训练。（自研小规模预训练 vs 开放底座，见 §5 未知项。）

**阶段 1：决策头热身（监督 + proper scoring rule）。**
- 训练对象：anchor embeddings + 标量打分头（骨干冻结或低学习率）；
- 数据：(state, question, candidates, **目标分布**) 大规模元组——注意目标是**分布**不是单标签（原因见 §3.1）；
- 损失：**Brier 优先于交叉熵**。Brier 有界，对"错但合理"的答案不会像 CE 那样被推向极端惩罚——对校准更友好；模糊样本天然以软分布为目标。
- NanoJev 的"Qwen3-0.6B 初始化 + 决策头预热 + 完整问题分布损失"与此完全一致。

**阶段 2：RLCD 主体（结果信号 + 校准奖励）。**
- 情景数据（游戏/浏览器/工具路由轨迹）上做策略优化（REINFORCE/GRPO 族），policy = 每问题的候选分布；
- 奖励构造：

```
r(p, y) = α · 1[argmax p = y]  −  (1−α) · Brier(p, y)
          └── 正确性项：保精度    └── 校准项：真值评分规则
```

- 两项的张力是**有意设计**：纯正确性奖励 → 过自信（"普通 RL 伤校准"是 RLCR 论文的核心发现）；纯校准奖励 → 模型可靠地输出中庸概率骗分。α 与数据难度课程共同决定"笃定—诚实"的操作点。RLCR 已证明：有界真值评分规则奖励 ⇒ 收敛到既准确又校准的策略。
- α 不必是常数：可按任务族/难度分度设置——这正是"校准的操作点写进训练配方"的含义。

**阶段 3：不变性与鲁棒轮。**
- 数据增强：同义改写（KL 一致性损失）、**随机 ID/噪声插入**（F10——官方的测试手段直接暴露了训练数据的构成）、候选乱序（分布应随排列置换）、近边界硬负例、OOD 状态（乱码/空/错语言 → 目标为平坦分布或"其他"高概率）；
- 损失：任务损失 + λ·KL(p(x) ‖ p(x′))。

**阶段 4：常设红队—再校准循环。** 对抗层不是阶段是流程（与官方"评估不能是一个阶段"的立场同构）。

### 2.3 评估口径（由目标反推）

按概率桶的可靠性图/ECE（校准是目标就必须按桶测）、Brier、**排列一致性**（选项换序分布应置换）、**改写一致性**（语义等价输入 KL 应小）、留出**任务族**（不是留出样本——测的是元技能泛化，防 Goodhart）。

## 3. 训练语料构建推导（本文最重要的部分）

### 3.1 校准对语料施加的特殊要求

**要训校准，就得知道每个样本的"真实概率"。** 而真实概率只有两类来源：**构造时可控**（合成时决定线索比例）或**多人标注可聚合**（分歧即分布）。这是全部语料设计的出发点，也是大多数复现项目校准失败的根因：

> **硬标签陷阱**：在模糊样本上用单标签训练，模型会把数据噪声当信号学——这是校准的经典杀手。Jev 的语料必须携带**分级目标**（graded targets）。

### 3.2 四个语料源

**源 1：受控合成任务生成器（主力，可扩展性与模糊度的来源）**

```
generate():
  1. 采样领域 d ~ 领域分类树（通讯/工单/代码/财务/合规/对话/游戏状态/…）
  2. 生成状态骨架 s：字段模板（嵌套 JSON、数组、点号路径）+ 实体填充
  3. 事实注入：向 s 植入受控线索集 L = {(线索, 方向, 强度)}
     → 目标分布 = normalize(Σ强度)         ★ 模糊度是生成器的旋钮
     例：紧急线索×3 vs 非紧急线索×1 → target {urgent: 0.75, not: 0.25}
  4. 采样问题 q：原子谓词模板 × 措辞改写器
     模板族：属性存在性 / 字段间匹配 / 程度评估 / 路由偏好 / 阈值比较 / 时序关系…
  5. 采样候选集 C：正确项 + 受控难度干扰项（近边界）+ "其他"
     干扰难度 = 与正确项的语义距离（可控）
  6. 输出 (s, q, C, target_distribution)
```

核心机制是第 3 步：**只有构造式合成能按需生产"已知真分布"的样本**。想让模型学会"这种 70/30 的情况就输出 0.7"，必须有无限量、真值恰为 0.7 的数据——随机真实数据给不了，LLM 蒸馏也给不了（LLM 自己不校准）。这个"模糊度旋钮"是语料构建的灵魂。

**源 2：多标注者软标签（真实分布的采样，金标准与校准锚）。**
真实语料每条多标注者打标 → 标注分布即目标分布。**人群 60/40 分歧的样本，正确目标就是 0.6**——分歧不是噪声，是校准信号。昂贵，故只用于锚定合成分布与真实分布的对齐。

**源 3：LLM 生成 + 验证（量的第二来源）。**
强 LLM 批量生成 (state, question, candidates) 与候选标签，程序化/人审抽验；**校准化 RLAIF**：多模型多次独立判断 → 投票分布做软目标（而非单标签蒸馏）。风险是 LLM 偏差被蒸馏 → 必须与源 1/2 混合，并周期性用源 2 的金集纠偏。

**源 4：情景/轨迹数据（RL 的燃料）。**
可程序化结算奖励的环境：游戏（迷宫/贪吃蛇/Doom）、浏览器任务、工具路由日志。state=观测，候选=动作，奖励=结果。这一源供给阶段 2，也解释了 Jev 为什么能打游戏——游戏 demo 不是玩具，是训练分布的自然产物。

### 3.3 课程与配比

```
清晰样本（教笃定：分布应尖锐）
  → 模糊样本（教诚实：分布应中庸）      ← 配比直接决定可靠性曲线形状
  → 对抗增强（教不变性：改写/乱序/噪声）
  → OOD（教弃权：平坦分布 / "其他"）
```

清晰:模糊的混合比例是**校准操作点的数据侧控制变量**——与阶段 2 的 α 共同构成"笃定—诚实"的完整调节面。量级估计（粗）：决策元组 10⁷–10⁸ 级、领域模板 10³–10⁴ 级，才能支撑"任意领域任意问题"的元技能。

### 3.4 问题空间的措辞多样性

推理时用户写任意 instructions——模型必须把任意表面形式映射到正确判断。所以源 1 第 4 步的**措辞改写器**不可省：同一原子判断要覆盖数十种表面形式（直接问句/条件句/否定式/嵌套 JSON 路径引用）。这是"判断的指令遵循"与聊天式指令遵循的本质区别：输出被约束在给定候选集上的分布。

### 3.5 为什么语料是壁垒（与复现证据互证）

- Laya：基础 checkpoint ≈ 随机（F11）→ 架构与预训练都不给决策能力，能力全部来自 §3.2 的四源数据；
- NanoJev：仅用迷宫+贪吃蛇数据就能在游戏任务上达 Jev 九成 → 数据配方对路时小模型够用；但单一领域数据无法解释 Jev 的跨域泛化 → 差距在生成器的**领域覆盖与模糊度控制**，不在网络结构；
- Raschka："秘诀更多在数据而非算法" → 与本推导一致。

## 4. 推导方案 vs 社区复现：一致性检验

## 6. 一句话总结

> **结构**：预训练亚十亿骨干 + 共享前缀（state）+ 独立打分的候选分支 + 单一"每问题一个 categorical 分布"readout，三种原语全是这个分布的算术投影。
> **训练**：决策头热身（软分布目标 + Brier）→ 结果信号 RL（正确性 + 真值评分规则混合奖励）→ 不变性轮 → 常设再校准。
> **语料**：以"模糊度可控的受控合成生成器"为主力，多标注者软标签为锚，LLM 生成+验证补量，可结算环境供 RL——**分级目标分布是全部语料设计的中心约束，也是最难复制的部分**。
